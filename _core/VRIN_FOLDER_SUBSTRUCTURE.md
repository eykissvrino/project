# VRIN 하위폴더 표준 — 00~05 안의 세부 구조 가이드

> 00~05 상위폴더(→ [`VRIN_PROJECT_STANDARD.md`](VRIN_PROJECT_STANDARD.md) §2)는 모든 프로젝트 공통.
> 그 **안의 세부 폴더**를 어떻게 나눌지에 대한 표준 — 표준 §2.1의 3대 원칙(최상위 00~05 고정·한글 `번호_이름`·깊이 2~3)을 상속·확장한다. 자동분류 STEP 3의 근거.
> **버전**: v1.0 · **제정**: 2026-06-18

---

## 0. 설계 원칙 — "척추는 표준, 살은 프로젝트별"

1. **폴더 이름이 아니라 '분할 축'을 표준화한다.** 각 상위폴더는 쪼개는 기준(축)이 정해져 있다.
   실제 폴더 이름은 그 축에 따라 프로젝트 내용에 맞게 생긴다.
2. **빈 폴더 미리 만들지 않는다(Lazy).** 같은 종류 파일이 **3개 이상** 쌓이면 그때 하위폴더로 묶는다.
   파일 1~2개는 상위폴더 직속에 둔다. (과분할 금지)
3. **최대 2단계까지만.** `04_산출물/최종보고서/그림/` 까지. 그 이상 깊어지면 못 찾는다.
4. **정렬은 번호 접두사**(`01_` `02_`), **날짜는 `YYYY-MM` 또는 `YYYYMMDD`**.
5. **프로젝트별 변형은 `00_관리/_폴더규칙.md`에 기록**(로컬 오버라이드). 2개+ 프로젝트서 반복되면 이 표준으로 승격(@CLO).

## 1. 폴더별 세부 구조 (분할 축 + 권장 폴더)

### 📌 00_관리 — 분할 축: **종류**
```
00_관리/
├── _브리프.md          (직속: 최초 과업·범위·성공기준 — 출발점, 거의 고정)
├── _기준선.md          (직속: 현행 기준 + 변경 이력 ⭐ 판단의 기준 → VRIN_PROJECT_LIFECYCLE.md)
├── _현황.md            (직속: 단계·상태·다음액션 — 대시보드 소스)
├── _스쿼드.md          (직속: 배정 AI팀)
├── _의사결정.md        (직속: 주요 결정 로그)
├── 회의록/             (회의록 3개+ 모이면) → 회의록_YYYYMMDD.md
├── 계약_행정/          (계약서·견적·발주·정산)
└── 일정_계획/          (간트·마일스톤·WBS)
```
> 핵심 관리문서(`_브리프`·`_현황`·`_스쿼드`)는 항상 **직속**. 누적되는 회의록·계약만 하위폴더로.

### 📌 01_입력자료 — 분할 축: **받은 시점** 또는 **출처**
```
01_입력자료/
├── 자료_2026-06/       (받은 월별 — 기본)
├── 발주처_제공/        (출처별로 갈 때: RFP·과업지시서·기존자료)
├── 데이터셋/           (원천 데이터·raw)
└── 참고양식/           (받은 서식·템플릿)
```
> **원본명 보존, 변형 금지.** 양이 적으면 `자료_YYYY-MM/` 하나로 시점별만. 출처가 뚜렷하면 출처별.

### 📌 02_지식리서치 — 분할 축: **주제**
```
02_지식리서치/
├── 문헌_논문/
├── 해외사례/
├── 국내사례/
├── 통계_데이터/
├── 벤치마킹/
├── 법령_제도/
└── _작업위키/          (프로젝트 작업 위키 — 승격 시 _wiki/로)
```
> 주제는 프로젝트마다 다르다. 위 목록은 자주 쓰는 후보일 뿐, 실제 주제명으로 만든다.

### 📌 03_작업실 — 분할 축: **작업 단위(모듈·트랙·단계)** ⭐ 프로젝트별 자유 영역
세 가지 패턴 중 프로젝트에 맞는 것을 고른다(섞지 말 것):

**(a) 모듈/트랙형** — 연구·다트랙 (예: KTR 훈련로드맵, 국가데이터처)
```
03_작업실/
├── M1_직무역량모델링/
├── M2_훈련체계설계/
└── _세션로그/
```
**(b) 컨설팅 7단계 오버레이형** — N170 흐름 컨설팅 (대표님 전통 흐름)
```
03_작업실/
├── 01_제안/  02_보고회/  03_실무진회의/  04_수행준비/
├── 05_수행/  06_성과공유/  07_보고서작업/
```
**(c) 산출물 작업형** — 만드는 산출물 단위 (예: 직무분석)
```
03_작업실/
├── 직무기술서_작업/
├── 분석/
└── _세션로그/
```
> 작업 메모·진행노트는 `_세션로그/`로 모은다.

### 📌 04_산출물 — 분할 축: **제출 회차 + 유형**
```
04_산출물/
├── .quality-log.md         (직속: @BAR A/B/C 등급)
├── 중간보고_20260610/       (제출 회차별 — 그 안에 보고서·발표자료 함께)
│   ├── 보고서/
│   └── 발표자료/
└── 최종보고서/
    ├── 보고서/   발표자료/   데이터/   그림/
```
> 회차가 여러 번이면 **회차별 폴더**가 1순위, 그 안에서 유형별. 단발이면 유형별만.

### 📌 05_보관 — 분할 축: **날짜**
```
05_보관/
├── 백업_20260618/
└── 구버전/
```

## 2. 프로젝트 유형별 시작 프리셋

### 🟦 유형 A — 컨설팅·연구 (기본)
- `03_작업실`: (a)모듈형 또는 (b)7단계형 또는 (c)산출물형 중 택1
- 나머지 00·01·02·04·05: §1 표준 그대로

### 🟩 유형 B — 개발 (홈페이지·웹앱·SaaS)
- **소스코드는 번호폴더 밖, 루트**(`app/ src/ package.json`).
- 번호폴더는 비코드 자산만:
  - `01_입력자료/`: 받은 브랜드자료·콘텐츠 원고
  - `02_지식리서치/`: 레퍼런스 사이트·기술조사
  - `03_작업실/`: `기획/`(PRD·IA) · `디자인/`(시안·와이어프레임)
  - `04_산출물/`: 배포본·캡처·산출 문서
- `00_관리`는 동일.

---

## 3. 자동분류 연계 (STEP 3에서 이 문서 사용)
- 분류 스킬은 파일을 상위폴더(00~05)에 넣을 때, 이 문서의 **분할 축**으로 하위폴더를 정한다.
- 해당 하위폴더가 없고 같은 종류가 3개+면 **신설**, 1~2개면 상위 직속.
- 프로젝트에 `00_관리/_폴더규칙.md`가 있으면 그것을 **우선** 따른다.
- 상세 동작: [`VRIN_FILE_CLASSIFICATION.md`](VRIN_FILE_CLASSIFICATION.md) §4.

## 4. 로컬 오버라이드 양식 (`00_관리/_폴더규칙.md`)
```markdown
# (이 프로젝트) 폴더 규칙 — 표준 오버라이드
- 03_작업실: 모듈형 사용 (M1 직무모델링 / M2 ...)
- 04_산출물: 회차 없이 유형별만
- (그 외는 _core/VRIN_FOLDER_SUBSTRUCTURE.md 표준 따름)
```
> 표준과 다르게 갈 때만 작성. 비워두면 전부 표준을 따른다.
