## 1. 최상위 — `projects/` 유지 + 업그레이드

```
vrin_AI_hub/projects/
├── _대시보드.md                      ← 전체 포트폴리오 현황 (cockpit.html 소스)
├── 2026-05_상하수도협회_직무분석/     ← 활성 프로젝트
├── 2026-01_장애인_HR솔루션/
├── 2026-02_AX진단도구/
└── _완료/                            ← 종료 프로젝트 보관 (연도별 하위)
    └── 2025/...
```

### 명명 규칙 (업그레이드 — 기존 `[N170]` 브랜드코드 폐기)

```
{연도}-{번호}_{고객사}_{사업명}
예) 2026-05_상하수도협회_직무분석
    2026-01_장애인_HR솔루션
```
- 연도-번호로 **정렬**, 고객사로 **식별**, 사업명으로 **검색**
- **단계·상태는 폴더명에 넣지 않음** → `00_관리/_현황.md`로 관리 → 진행돼도 폴더명 불변
- 법인 구분 필요 시 `00_관리/_현황.md`에 메타(시앤피/대우)로 기록

## 3. 두 가지 프로젝트 유형 (같은 척추, 다른 살)

### 🟦 유형 A — 컨설팅·연구·사업형 (기본)
- 모든 작업 `03_작업실/`, 최종 `04_산출물/`
- **컨설팅 오버레이**(대표님 N170 흐름 — `03_작업실/` 내 단계 폴더 선택):
  `01_제안 → 02_보고회 → 03_실무진회의 → 04_수행준비 → 05_수행 → 06_성과공유 → 07_보고서작업`

### 🟩 유형 B — 개발형(소프트웨어)
- 소스코드는 **루트**(`app/ lib/ package.json`) — 빌드도구 요구
- 번호폴더는 비코드 자산만: `00_관리 / 01_입력자료 / 02_지식리서치 / 04_산출물`
- 예: 나라장터 웹앱, 홈페이지, SaaS, 진단도구

## 4. 스쿼드 — 프로젝트는 부서에서 차출한다

```
프로젝트 생성 → @CoS가 과업 분석 → 부서에서 팀원 차출 → .claude/agents/ 배치
            → 00_관리/_스쿼드.md 기록 → 7단계 수행 → 종료 시 해산(부서 복귀)
```
- 프로젝트 `.claude/agents/` = **그 프로젝트의 실제 스쿼드 명단**
- 필요 전문가 없으면 즉석 신설(계약직) → 검증되면 부서 정규직 승격 (↓5)

## 5. 성장 루프 — 3대 자산이 함께 자란다 ⭐

```
              프로젝트 로컬                      글로벌 (모든 미래 프로젝트 상속)
  에이전트   .claude/agents/      →승격→        _core/agents/ (부서 로스터)
  스킬       .claude/skills/      →승격→        _core/skills/ · ~/.claude/skills/
  지식       02_지식리서치(작업위키) →승격→       _wiki/ (회사 위키)  ← VRIN_SECOND_BRAIN §
```

**승격 판정(@CLO 분기)**: 2개+ 프로젝트서 필요? @BAR 통과 3회+? 기존과 중복? → 글로벌 승격 or 로컬 유지 or 폐기.

**프로젝트 종료 의식**: ① 중간작업물 보존(지식자산) ② 04_산출물→루트 outputs 인덱스 ③ 재사용 지식→`_wiki/` 환원 ④ 폴더째 `projects/_완료/{연도}/` 이동.

## 6. 신규 프로젝트 생성 플로우

```
"새 프로젝트: {명}" → @CoS:
  1. 유형 선택 (A/B)   2. 번호 부여 (2026-NN)
  3. 표준 골격 생성     4. 스쿼드 차출(도메인 매칭)
  5. _wiki/ 질의 → 01·02 자동 시딩 (제로베이스 금지)
  6. _대시보드 등록
```
→ `new-project.cmd`/`.sh`를 이 표준으로 갱신 (Build Plan Phase 2).
