# 자기진화 루프 (System Evolution Loop)

> 이 워크스페이스가 **시간이 갈수록 더 똑똑해지도록** 만드는 지속 업데이트 메커니즘.
>
> **설계 원리**: @BAR 검증 루프(품질 검증) + @CLO(자기진화) + 정기 점검(정합성)을 시간 축에 따라 결합.
> **최종 업데이트**: 2026-05-28

---

## 1. 비전

```
        ┌───────────────────────────────┐
        │   매 산출물 → @BAR 검증 루프      │ ← 즉시
        │   매주     → 패턴 수집         │ ← 주간
        │   매월     → 정합성 점검       │ ← 월간
        │   매분기   → @CLO 진화 사이클  │ ← 분기
        │   매년     → 외부 백업         │ ← 연간
        └───────────────────────────────┘
                       ↓
        시스템이 스스로 진화하는 자생 메커니즘
```

### 4가지 진화 원천
1. **품질 누적** — 매 산출물의 등급이 쌓이면서 약점·강점 노출
2. **사용 데이터** — 어떤 스킬·에이전트가 자주 호출되는지 추적
3. **사용자 피드백** — 새 패턴·요구사항을 정기 수집
4. **외부 변화** — 신규 법령·기술·플랫폼 반영

---

## 2. 진화 주기 4단계

### 🔁 매 산출물 — @BAR 검증 루프 (즉시)

#### 트리거
- 모든 산출물(보고서·제안서·분석·코드 등) 생성 시 자동

#### 흐름
```
초안 작성 (담당 에이전트, 예: @HR·@DEL)
    ↓
@BAR 비판자 모드 자가 검증
  - 품질계약(QUALITY_CONTRACT) 기준 5+6항목 체크
  - 누락·모순·근거 부족 탐지
    ↓
수정 (1~3회 반복)
    ↓
등급 부여 (A/B/C)
    ↓
산출물 메타데이터 기록
  → projects/{프로젝트}/outputs/.quality-log.md
```

#### 산출물
- 품질 등급 라벨 (A: 즉시 사용 / B: 부분 보완 / C: 재작업)
- 검증 코멘트 (어떤 부분이 약했는지)

#### 누적 효과
- 매월·매분기 등급 누적 분석 → 스킬 약점 식별

---

### 📅 매주 월요일 — 패턴 수집 (주간)

#### 트리거
- 매주 월요일 (사용자 또는 workspace-manager)
- 또는 "이번 주 정리해줘" 한국어 트리거

#### 흐름
```
지난 주 활동 회고
    ↓
신규 패턴 후보 수집
  - 반복된 새 작업 → 스킬 후보
  - 반복된 새 문제 → 가이드 후보
  - 자주 호출된 외부 도구 → MCP·플러그인 후보
    ↓
"WEEKLY_BRIEF.md" 임시 작성
    ↓
사용자 검토 (5분)
    ↓
승인 항목만 → 분기 @CLO 진화 사이클 대상으로 등록
```

#### 산출물
- `_core/evolution/weekly/{YYYYMMDD}_WEEKLY_BRIEF.md`
- 신규 스킬·가이드 후보 리스트

#### 권장 시간
- 월요일 오전 10분

---

### 📆 매월 말일 — 정합성 점검 (월간)

#### 트리거
- 매월 마지막 영업일 (workspace-manager 자동 또는 사용자 요청)
- "이번 달 워크스페이스 점검해줘"

#### 점검 항목 — 7가지
| # | 점검 | 도구 |
|---|------|------|
| 1 | REGISTRY.md vs 실제 폴더 (스킬·에이전트·워크플로우 수) | diff |
| 2 | 활성 프로젝트 목록 vs `projects/` 폴더 | ls + diff |
| 3 | 가이드 문서들의 상호 일관성 (수치·경로) | grep |
| 4 | 디바이스 패리티 (노트북·데스크탑) | DEVICE_PARITY_CHECKLIST |
| 5 | 산출물 품질 등급 통계 (A/B/C 비율) | .quality-log.md 집계 |
| 6 | 에이전트별 호출 빈도 | 세션 로그 분석 |
| 7 | 미커밋 Git 변경 사항 | git status |

#### 흐름
```
workspace-manager가 7가지 점검 자동 실행
    ↓
"MONTHLY_HEALTH_REPORT.md" 작성
    ↓
사용자에게 요약 보고
    ↓
즉시 조치 가능한 것 → 자동 수정 (가이드 수치 갱신 등)
중대 조치 → 분기 @CLO으로 이월
```

#### 산출물
- `_core/evolution/monthly/{YYYYMM}_HEALTH_REPORT.md`

---

### 🔄 매분기 (3·6·9·12월) — @CLO 진화 사이클 (분기)

#### 트리거
- 매분기 마지막 주 (예: 3월 4째주, 6월 4째주 등)
- "분기 진화 시켜줘" 또는 "@CLO 돌려줘"

#### @CLO 5단계
```
1. 관찰 (Observe)
   - 지난 3개월 산출물 등급·에이전트 사용·신규 패턴 종합
    ↓
2. 패턴 (Pattern)
   - 반복된 약점 / 자주 쓴 새 방법 / 안 쓰이는 리소스
    ↓
3. 개선 (Improve)
   - 스킬 보강·신규 스킬·에이전트 권한 조정·가이드 개정
    ↓
4. 시험 (Trial)
   - 다음 1~2주간 실제 작업에 적용
    ↓
5. 승격 또는 폐기 (Promote/Retire)
   - 효과 입증 → _core/에 정식 등록
   - 미사용 → archive/legacy-resources/로 이관
```

#### 주요 산출물
- 신규 스킬 1~3개 (검증된 패턴이 스킬화)
- 폐기 리소스 목록 (안 쓰이는 에이전트·스킬)
- 가이드 개정안 (CLAUDE.md, REGISTRY.md, WORKSPACE_GUIDE.md)
- 다음 분기 진화 우선순위 3가지

#### 파일
- `_core/evolution/quarterly/{YYYYQX}_PYGMALION_REPORT.md`
- `_core/agents/v2/clo.md` (@CLO 학습진화실 — 진화 사이클 수행)

## 6. 진화 후보 → 정식 승격 기준

신규 스킬·가이드가 `_core/`에 정식 등록되려면:

### 스킬 (Tier 2 승격)
| 기준 | 통과 조건 |
|------|----------|
| 사용 빈도 | 분기 내 3회 이상 반복 사용 |
| 효과성 | @BAR 검증 루프 평균 등급 B 이상 |
| 일반화 가능 | 2개 이상 다른 프로젝트에 적용 가능 |
| 문서화 | SKILL.md에 트리거·프로세스·예시 완비 |

### 에이전트 (신규 그리스신화 추가)
| 기준 | 통과 조건 |
|------|----------|
| 도메인 명확성 | 기존 9명과 겹치지 않는 영역 |
| 호출 빈도 | 분기 내 10회 이상 호출 |
| 활용 스킬 2개 이상 | 단일 스킬 호출이면 스킬로 충분 |

### 가이드 문서 개정
| 기준 | 통과 조건 |
|------|----------|
| 실제 변경 | 시스템 구조·번호 체계 등 영구 변경 |
| 영향 범위 | 다른 가이드 3개 이상에 영향 |
| 사용자 승인 | @CLO 진화 사이클 4단계에서 확정 |

## 7. 자기진화의 안전 장치

### 후퇴 가능성 (Rollback)
- 모든 분기 @CLO 결과는 Git 커밋으로 보존
- 새 스킬·가이드 도입 후 1개월 내 효과 없으면 `archive/legacy-resources/`로 후퇴
- 폐기된 리소스도 6개월 보관 후 영구 삭제

### 진화 폭주 방지
- 분기당 신규 스킬 최대 3개
- 신규 에이전트 최대 1명/년
- 가이드 문서는 분기 1회만 개정 (긴급 수정 제외)

### 사용자 통제
- 자동화는 "점검·제안"까지만
- "정식 등록"·"폐기"는 항상 사용자 승인 필요
