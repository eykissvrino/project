# VRIN 지식 체계 — Second Brain + LLM Wiki (v2.1)

> 우리 체계의 지식 층. **Second Brain(서랍 — 어디에 두나)** 위에 **LLM Wiki(살아있는 백과사전 — 복리로 쌓이나)**를 얹는다.
> 핵심: **"제로베이스로 시작하지 않는다 — 회사 위키에 물어보면 이미 정리돼 있다."**
>
> **상태**: v2.1 확정 · **개정**: 2026-06-15 · 상위: [`VRIN_ORG_SYSTEM.md`]

---

## 1. 두 레이어 — 보완 관계

```
Second Brain (PARA 분류)   = 서랍.   원본·자료를 어디에 보관하나 (WHERE)
        +
LLM Wiki (Karpathy)        = 백과사전. 지식이 어떻게 복리로 쌓이나 (HOW)
```
RAG처럼 매번 원본을 다시 뒤지지 않는다. **LLM이 위키를 지속 갱신** — 새 자료를 기존 페이지에 통합, 교차참조, 모순 표시. "이미 정리돼 있다."

---

## 2. PARA — 분류 원칙 (폴더 강제 아님, 사고 틀)

> 대표님 피드백 반영: `projects/` 최상위 유지. PARA는 **분류 사고 틀**로만 사용.

| 카테고리 | 정의 | VRIN 위치 |
|----------|------|-----------|
| **프로젝트** | 종료일 있는 활성 과제 | `projects/` |
| **영역** | 끝없는 책임 분야 | `areas/` (시앤피경영·HR솔루션팀·MBA·월인가) |
| **자원** | 참고·관심 지식 | `_wiki/` (회사 위키로 흡수) |
| **아카이브** | 종료된 것 | `projects/_완료/` |
| **수집함** | 빠르게 모음 | `0_수집함/` 또는 Notion (폰 수집) |

---

## 3. LLM Wiki — 3-레이어 구조 ⭐

```
1. 원본(불변)   →  프로젝트 01_입력자료/  ·  외부 자료
2. 위키(생성)   →  _wiki/                 (회사) · 프로젝트 02_지식리서치/ (작업)
       _wiki/
       ├── index.md     카테고리별 목차 (자동 유지)
       ├── log.md       활동 append-only 로그
       ├── schema.md    위키 구조·규칙·워크플로우 정의
       └── pages/       교차참조된 지식 페이지 + 엔티티 (직무분석방법론, NCS, 고객사 등)
3. 운영        →  Ingest · Query · Lint
```

### 3대 운영 ↔ 조직 ↔ OMC 도구

| 운영 | 하는 일 | 담당 | OMC 도구 |
|------|--------|------|---------|
| **Ingest** | 새 자료 → 위키 통합·교차참조·로그 | `@RES`(`res-wiki` 사서) | `wiki_ingest`·`wiki_add` |
| **Query** | 위키 검색 → 출처와 함께 종합 → 가치 있으면 새 페이지로 환원 | `@RES` | `wiki_query`·`wiki_read` |
| **Lint** | 모순·고아페이지·공백 점검 (분기) | `@CLO` 학습진화실 | `wiki_lint`·`wiki_list` |

> 사람(대표)=큐레이션·전략 / LLM=유지·요약·교차참조·정리. 지식베이스가 썩지 않게.

## 4. 제로베이스 금지 — 새 프로젝트는 위키를 상속

```
새 프로젝트 "{명}" 생성
   ↓
@CoS → @RES가 _wiki/ Query (탐색+검색)
   예) "직무분석" → 위키의 직무분석 방법론·NCS·유사 용역(과거 N170) 페이지 즉시 호출
   ↓
정리된 지식 → 프로젝트 02_지식리서치/ 에 시딩 + 출처 링크
   ↓
"빈 폴더가 아니라, 11년치 정리된 지식 위에서 시작"
```

---

## 5. 통합 승격 — 지식도 함께 자란다

```
프로젝트 02_지식리서치 (작업 위키)  →[검증·재사용]→  _wiki/ (회사 위키)
프로젝트 종료 시 중간작업물·인사이트 → _wiki/pages/ 로 환원 (@CLO Learn)
```
→ [`VRIN_PROJECT_STANDARD.md`] §5 의 3대 자산(에이전트·스킬·**지식**) 승격과 동일 원리.

## 6. 프로젝트 코드 규칙 (대표님 실무 관행 보존, 단 폴더명은 신규 표준)

기존 실무 코드(`[N170]`, `[25Y008]`, `Q705`)는 **메타데이터**로 `00_관리/_현황.md`에 보존.
폴더명은 신규 표준 `{연도}-{번호}_{고객사}_{사업명}` 사용 ([`VRIN_PROJECT_STANDARD.md`] §1).
