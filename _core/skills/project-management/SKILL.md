# 프로젝트 실행 관리 스킬 (Project Management)

> 범용 프로젝트 진행·일정·품질·리스크 관리 골격. P2026-003·P2026-010에서 검증된 패턴을 일반화.
> VRIN 표준 `00_관리/_현황.md`(대시보드 소스) 및 7단계 스프린트와 연계한다.

## 목적
단일/다중 워크스트림(기업·과업·트랙)을 병행 수행하며 일정·품질·리스크 편차를 통제한다.

## 1. 진행 현황 추적 — `00_관리/_현황.md`

```markdown
# {프로젝트} 진행 현황 (업데이트: YYYY-MM-DD)

## 7단계 위치
Frame · Plan · **Produce(현재)** · Critique · Validate · Deliver · Learn

## RAG 상태
🟢 정상 / 🟡 주의 / 🔴 지연

## 워크스트림 보드 (다중 트랙 시)
| 트랙/대상 | 단계 | 상태 | 담당 | 다음 액션 | 마감 |
|-----------|------|------|------|----------|------|
| (예: 트랙A) | M2 | 🟢 | @부서 | … | MM-DD |
```

## 2. 마일스톤 관리
- 프로젝트를 단계(M1·M2…)로 분해, 각 단계의 **완료 정의(DoD)** 명시
- 표준 마일스톤: 착수 → 중간보고 → 단계별 완료 → 최종보고 → 성과공유
- 각 마일스톤에 날짜·산출물·승인주체(@BAR 검증 포함) 연결

## 3. 품질 관리 체크리스트 (산출물 단위)
- [ ] 과업 정의(_브리프)의 성공기준 충족
- [ ] 근거(데이터·이론·사례) 제시
- [ ] 프레임워크 적용 적절성
- [ ] 고객/이해관계자 확인·합의
- [ ] @BAR 독립검증 통과 (A/B/C) — 셀프승인 금지

## 4. 리스크 관리
| 유형 | 신호 | 대응 |
|------|------|------|
| 일정 지연 | 마감 임박·선행과업 미완 | 버퍼 운영, 우선순위 재배치 |
| 품질 편차 | 트랙 간 산출물 수준 차이 | 표준 양식·기준 사전 합의 |
| 요구 변경 | 범위 추가·변경 | 변경관리 → `00_관리/_기준선.md` 갱신(현행 기준+이력) |
| 자원 부족 | 전문 역량 공백 | @CoS에 스쿼드 추가 차출 요청 |

### 4.1 기준선(Baseline) 관리 ⭐
처음 RFP·과업지시서·제안서는 출발점일 뿐, 착수·중간·최종 보고를 거치며 합의로 바뀐다.
- **현행 기준 = 최신 합의본** (충돌 시 최신 합의 > 이전 > 원본). 판단은 항상 `_기준선.md` 기준.
- 보고 단계마다 범위·기준 변경분을 `_기준선.md`에 기록, 원본은 보존.
- @BAR 검증·산출물 평가는 원본 RFP가 아니라 **현행 기준** 대비. → [`_core/VRIN_PROJECT_LIFECYCLE.md`](../../VRIN_PROJECT_LIFECYCLE.md)

## 5. 명령어(자연어 트리거)
- "현황 업데이트" → `_현황.md` 갱신 → cockpit 반영
- "진도 요약" → 전체 워크스트림 상태 요약
- "[대상] 진도" → 특정 트랙 상세
- "마일스톤 체크" → 달성 여부 점검
- "리스크 점검" → 식별·대응 현황

## 연계
- 표준 구조: `_core/VRIN_PROJECT_STANDARD.md` (§2 폴더·§4 스쿼드·§6 생성)
- 대시보드: `cockpit.html` ← `00_관리/_현황.md` 집계
- 검증: @BAR · 진화/학습 환원: @CLO
- 운영 주체: @CoS(PMO) — 라우팅·스쿼드·스프린트 운영

> 도메인 특화 진행관리(예: 장애인 직무 5M·10S)는 프로젝트 로컬 스킬로 두고, 이 범용 골격을 상속·확장한다.
