# VRIN 파일 자동분류 기준서 (Classification Rulebook)

> 던져진 파일을 **분석 → 어느 프로젝트 / 어느 폴더(00~05) / 어느 하위폴더**로 보낼지 결정하는 규칙.
> 이 문서는 `file-classification` 스킬의 두뇌다. 상위 표준: [`VRIN_PROJECT_STANDARD.md`](VRIN_PROJECT_STANDARD.md)
> **버전**: v1.0 · **제정**: 2026-06-18 · **운영원칙**: 확신 건은 자동 / 애매하면 질문 / 이동 전 로그

---

## 0. 핵심 원칙 (대표님 승인)

1. **확신(High)이면 자동 이동, 애매(Low)하면 질문** — 추측으로 옮기지 않는다.
2. **삭제·덮어쓰기 금지** — 분류는 "이동(move)"이지 삭제가 아니다. 이름 충돌 시 `_v2`·날짜 suffix.
3. **모든 이동은 로그에 기록** — `_INBOX/_분류로그.md`에 기록 → 언제든 되돌리기 가능.
4. **원본 보존 원칙** — `01_입력자료`(고객이 준 raw)는 절대 가공·이동 후 변형하지 않는다.

---

## 1. 결정 절차 (3단계)

```
파일 1개
 ├─ STEP 1. 어느 프로젝트?   (없으면 → _INBOX/_미분류/ 보류 + 질문)
 ├─ STEP 2. 어느 폴더(00~05)? (즉답표 + 신호)
 └─ STEP 3. 어느 하위폴더?    (없으면 규칙대로 신설)
        ↓
   확신도 판정 → High: 자동 이동 / Low: 분류계획표에 ❓표시 후 질문
```

### 두 종류의 인박스
| 위치 | 의미 | 절차 |
|---|---|---|
| **루트** `_INBOX/` | "어느 프로젝트인지 모름" | STEP 1→2→3 전부 수행 |
| **프로젝트별** `projects/<프로젝트>/_INBOX/` | "이 프로젝트인 건 확정" | **STEP 1 생략**(위치=프로젝트). STEP 2→3만. 분류 대상은 그 프로젝트 폴더 내부로 한정 |

> 프로젝트별 인박스는 위치가 곧 프로젝트이므로 오분류 위험이 낮다. 폴더(00~05)·하위폴더만 판단하면 된다.

## 2. STEP 1 — 어느 프로젝트인가

> ⚠️ 프로젝트 목록은 **고정이 아니다**. 스킬은 매 실행 시 `projects/`를 다시 스캔하고
> 각 프로젝트의 `CLAUDE.md`·`README.md`를 읽어 키워드를 갱신한다. 아래는 2026-06-18 스냅샷.

### 판정 신호 (강→약)
1. **파일명에 프로젝트코드** (`P2026-006`, `2026-06`) → 거의 확정 (High)
2. **고객사명·기관명** 파일명/내용에 등장 → 강한 신호
3. **사업 주제 키워드** (직무분석·훈련로드맵·AX진단 등) → 중간 신호
4. 위 신호 2개 이상 일치 → High / 1개 약신호만 → Low(질문)

## 3. STEP 2 — 어느 폴더(00~05)인가

### 즉답표 (VRIN_PROJECT_STANDARD §2 그대로)
| 폴더 | 들어가는 것 | 자동분류 신호 |
|---|---|---|
| `00_관리` | 일정·회의·브리프·스쿼드·현황·계약·의사결정 | 회의록, 일정, 계약서, 견적, 발주, _브리프, _현황, 카톡/메일 캡처 |
| `01_입력자료` | **고객이 준 원본** (내가 만든 것 아님) | 발주처 제공 RFP·과업지시서·기존자료·데이터셋·"○○ 제공", 받은 첨부 원본 |
| `02_지식리서치` | 참고 이론·조사·분석·문헌 | 논문, 해외사례, 벤치마킹, 통계자료, 위키, 참고문헌 |
| `03_작업실` | **작업 중 초안·중간물** | draft, 초안, v0.x, WIP, 분석노트, 중간산출, 작업본 |
| `04_산출물` | **고객에게 갈 최종본** | 최종, final, 제출, 보고서(완성), 발표자료(완성), v1.0+, 납품 |
| `05_보관` | 옛 버전·폐기 | old, 구버전, deprecated, ~백업 |

### 가장 헷갈리는 3분기 — 입력 vs 작업 vs 산출
- **누가 만들었나?** 고객/외부가 줬다 → `01_입력자료`. 우리가 만들었다 → 03 또는 04.
- **완성도?** 초안·중간 → `03_작업실`. 제출/납품용 완성본 → `04_산출물`.
- 판단 근거가 약하면 → **Low(질문)**. 특히 "보고서.docx"처럼 초안인지 최종인지 불명확하면 묻는다.

### 개발형 프로젝트(유형 B) 예외 — P2026-005, 월인가 홈페이지 등
- **소스코드**(`.html .jsx .tsx .ts .js .css .py package.json` 등)는 번호폴더가 아니라 **프로젝트 루트**(또는 `app/ src/`)로.
- 번호폴더(00~04)에는 **비코드 자산만** (기획·디자인시안·받은 자료·산출 문서).

## 4. STEP 3 — 어느 하위폴더인가 (없으면 신설)

> "폴더 안에 새 폴더를 구축해 체계화" = 이 단계. **하위폴더는 규칙대로 자동 생성**한다.
> **정본 규칙**: [`VRIN_FOLDER_SUBSTRUCTURE.md`](VRIN_FOLDER_SUBSTRUCTURE.md) (분할 축·유형별 프리셋).
> 프로젝트에 `00_관리/_폴더규칙.md`가 있으면 **그것을 우선** 적용한다. 아래는 요약.

### 폴더별 하위 분류 규칙
| 상위 | 하위폴더 규칙 | 예 |
|---|---|---|
| `00_관리` | 종류별 | `회의록/`, `계약_견적/`, `일정/`, (`_브리프.md`·`_현황.md`·`_스쿼드.md`는 상위 직속) |
| `01_입력자료` | **받은 월별** 또는 출처별 | `자료_2026-06/`, `발주처_제공/`, `데이터셋/` |
| `02_지식리서치` | 주제별 | `해외사례/`, `문헌/`, `통계/`, `벤치마킹/` |
| `03_작업실` | **모듈/트랙별** 또는 단계별 | `M1_직무모델링/`, `01_제안/`, `분석/` (컨설팅 오버레이 7단계 사용 가능) |
| `04_산출물` | **버전/제출회차별** + 유형별 | `최종보고서/`, `발표자료/`, `중간보고_0610/` |
| `05_보관` | 날짜별 | `백업_2026-06-18/` |

### 하위폴더 신설 판단
- 같은 종류 파일이 **3개 이상** 쌓이면 하위폴더로 묶는다. (예: 회의록 3개 → `회의록/`)
- 날짜/모듈/회차가 파일명·내용에 뚜렷하면 그 기준으로 신설.
- 애매하면 상위폴더 직속에 두고, 나중에 묶는다(과분할 금지).

### 파일명 표준화 (선택 — 명백할 때만)
`{프로젝트코드}_{유형}_{날짜YYYYMMDD}_v{버전}.{확장자}`
예: `P2026-006_직무기술서_20260618_v1.docx`
> 원본 파일명이 의미 있으면 함부로 바꾸지 않는다. `01_입력자료`의 원본명은 보존.

## 4.5 생애주기 문서 + 기준 변경 감지 ⭐
> 상세: [`VRIN_PROJECT_LIFECYCLE.md`](VRIN_PROJECT_LIFECYCLE.md). 처음 RFP·과업지시서·제안서는 **출발점이지 영원한 정답이 아니다.**

**생애주기 문서 라우팅**
| 문서 | 위치 |
|---|---|
| 제안요청서(RFP)·과업지시서 | `01_입력자료/발주처_제공/` (발주처 원본) |
| 제안서·제안발표자료 | 확정본 `04_산출물/01_제안/` (초안은 `03_작업실/01_제안/`) |
| 착수/중간/최종 보고서 | `04_산출물/{착수\|중간\|최종}보고_YYYYMMDD/` (회차별) |
| 수정·보완 최종본 | `04_산출물/최종보고서/`(현행) + 직전본 `05_보관/` |

**기준 변경 감지 규칙** (자동 단정 금지)
- 새로 들어온 보고서/회의록/공문이 기존 기준과 **달라 보이면**, 파일은 회차/단계별로 정리하되
  **"기준 변경으로 보입니다 (예: 제안서 20개 ↔ 이 중간보고 18개)"**라고 알리고, 기준 갱신은 **사람 확인**을 받는다.
- 확인되면 `00_관리/_기준선.md`(현행 기준 + 변경 이력)를 갱신. 원본·이전본은 보존(삭제·덮어쓰기 금지).
- 판단 기준은 항상 `_기준선.md`의 **현행 기준**(원본 RFP가 아님).

## 5. 확신도(Confidence) 판정 → 행동

| 등급 | 조건 | 행동 |
|---|---|---|
| **High (자동)** | 프로젝트 신호 강(코드/고객사) + 폴더 신호 명확 | 바로 이동 + 로그 |
| **Mid** | 프로젝트는 확실, 폴더가 1개 후보로 자연스러움 | 이동하되 로그에 근거 명시 |
| **Low (질문)** | 프로젝트 불명 / 입력·작업·산출 분기 모호 / 신호 충돌 | `_미분류/` 보류 + 분류계획표에 ❓ → 한 번에 모아 질문 |

**질문은 모아서 한 번에.** 파일마다 따로 묻지 않고, 한 배치 끝에 ❓목록을 표로 제시한다.

## 6. 파일 유형별 내용 분석 방법 (스킬이 사용)

| 확장자 | 분석 방법 |
|---|---|
| `.txt .md .csv .json .html` | Read 도구로 직접 읽기 |
| `.hwp .hwpx` | hwp-mcp(`read_hwp_text`)로 본문 추출 |
| `.docx` | docx 스킬 / 텍스트 추출 |
| `.pdf` | pdf 스킬 / Read(pages) |
| `.pptx` | pptx 스킬 / 슬라이드 텍스트 |
| `.xlsx` | xlsx 스킬 / 시트 헤더 |
| `.png .jpg` | 파일명 + (필요시) 이미지 Read로 내용 추정 |
| 코드/기타 | 확장자·파일명·경로로 판정 (유형 B 규칙) |

> 대용량(>50MB)·바이너리는 내용을 깊게 안 읽고 **파일명+확장자**만으로 판정, 애매하면 Low.

## 7. 안전장치 요약
- 이동 전 **분류계획표** 제시(자동분 + ❓질문분 구분).
- 모든 이동은 `_INBOX/_분류로그.md`에 `날짜 | 원본경로 → 대상경로 | 근거` 기록.
- 되돌리기: 로그를 역순으로 mv 하면 원상복구.
- 충돌 시 덮어쓰기 금지(suffix). 삭제 절대 금지(05_보관 이동으로 대체).
