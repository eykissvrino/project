## 0. 설계 원칙

1. **단일 진실 원천(Single Source of Truth)**: 모든 데이터는 **프로젝트 성과관리 시트(.xlsx)** 에 1회만 입력. 공단 보고서는 프로젝트 성과관리 시트에서 **추출·재구성**한 결과물.
2. **주간 1사이클**: 월요일 프로젝트 성과관리 시트 갱신 → 화요일 오전 보고서 생성 → 화요일 오후 공단 송부 (작년 보고 주기와 동일하게 수요일 송부도 가능)
3. **점진적 정보 밀도**: 사업 단계(M1→M5)가 진행될수록 보고서 정보 밀도가 자연스럽게 증가. 양식은 고정.
4. **리스크 가시성**: 작년의 "이슈사항: 없음" 패턴 탈피. 리스크는 프로젝트 성과관리 시트에서 트래킹되고, 보고서에는 자동 노출.
5. **B2B 전환 기록**: P2026-001 연계 — 기업별 추가 니즈·관계 진전을 별도 탭에서 누적.
6. **가나다순 일관**: 모든 기업 목록은 가나다순(성불복지회 → 해양환경공단). 단, 컨설턴트별 묶음 보기는 별도 뷰.

## 2. 프로젝트 성과관리 시트 탭 구성 (총 5개 탭) — v0.4 단순화

> **단순화 원칙**: 심플(꼭 필요한 것만) + 체계적(누가 봐도 한 번에 이해) + 피드백 가능(코멘트 누적)
> v0.3의 11개 탭 → v0.4는 **5개 탭**. Dashboard·자동 빌더·복잡한 자동화는 Phase 2(시범 운영 후 추가)로 후순위.

| # | 탭명 | 목적 | 주 사용자 | 갱신 주기 |
|---|------|------|----------|----------|
| 1 | **기업 마스터** | 8개 기업 기본정보 + 컨설턴트 + 담당자 + 현재 단계 | 전체 | 변경 시 |
| 2 | **진행 매트릭스** | 5M·10S × 8개 기업 진행현황 + 일정 (작년 보고서 §1 그대로) | 컨설턴트 → PL | 주 1회(월) |
| 3 | **직무 트래커** | 후보군 Pool + 평가점수 + 최종 선정 직무 + 산출물 진척 | 컨설턴트 | M2 단계+ |

| 5 | **B2B 전환 트래커** ★ | 기업별 추가 니즈, P2026-001 영업 단계 | 이석주(PL) | M5 단계+ |

★ = 작년 대비 신규

### 2.1 탭별 핵심 필드

#### 탭 1. 기업 마스터
- 8개 기업 = 8행 고정. 한 행에 모든 기본정보가 모임 (다른 탭의 마스터 데이터)
- 열: `연번 / 기업명 / 기업형태 / 업종 / 소재지 / 상시근로자 / 장애인근로자 / 고용예정인원 / Main 컨설턴트 / Sub 컨설턴트 / 기업 담당자명 / 직위 / 연락처 / 이메일 / 현재 단계(M1~M5) / 비고`

#### 탭 2. 진행 매트릭스 (가장 핵심, 공단 보고서 §1과 1:1 매칭)
- 작년 보고서 §1의 5M·10S 매트릭스 + 워크숍 일정을 **하나의 시트에 통합**
- 가로축: S1~S10 (10개 컬럼) / 세로축: 8개 기업 (가나다순)
- 셀 값: `[일자]` 또는 `완료` / `진행중` / `예정` / `-`
- 셀 주석(comment): 시간·장소·참여자·자료 링크 (= 워크숍 일정 정보를 셀 주석으로 통합)
- 색상 코드 (조건부 서식): 완료=연두 / 진행중=노랑 / 지연=주황 / 예정=회색
- 우측 메타 컬럼: 현재 단계 / 다음 마일스톤 / Main 컨설턴트

#### 탭 3. 직무 트래커
- 기업별 직무 후보 → 평가 → 선정 → 프로파일·산출물까지 **하나의 시트에서 추적**
- 단계 진행에 따라 컬럼이 채워지는 구조 (M2 발굴 → M3 평가 → M4 프로파일 → M5 활용)
- 열: `기업 / 직무명 / 유형(실행가능/전략확산) / 평가점수(M3) / 선정여부(★대표/선정/예비/탈락) / 직무기술서 상태 / 직무명세서 상태 / 활용·확산도구(개수) / 비고`
- 약 16~24행 예상 (기업당 직무 2~3개)

#### 탭 4. 이슈·피드백 로그 ★ 핵심 (피드백 가능 원칙의 중심)
- 리스크·이슈 + 회의 후 피드백 + 기업측 코멘트 + 내부 결정 → **하나의 로그에 누적**
- 작년 양식의 약점("이슈사항: 없음" 형식 답변)을 직접 보완
- 열: `ID / 식별일 / 기업 / 유형(리스크·이슈·기업피드백·내부코멘트·결정) / 제목 / 내용 / 출처(누가·어디서) / 심각도(High/Med/Low) / 담당자 / 대응·답변 / 마감일 / 상태(Open/진행/완료) / 해결일 / 공단보고 포함여부`
- "유형" 컬럼으로 리스크/일반 피드백/회의록 코멘트 구분
- "공단보고 포함여부=Y"인 항목만 주간 보고서 §3에 노출

#### 탭 5. B2B 전환 트래커 ★ 신규 (P2026-001 사업 연계)
- 기업당 1행, 8행 고정. M5 단계부터 본격 채움
- 열: `기업 / B2B 가능성(High/Med/Low/미평가) / Land&Expand 단계 / 추가 니즈 / 의사결정권자 / 다음 액션 / 다음 액션 마감일 / 영업 메모`

### 2.2 Phase 2 후보 (시범 운영 후, 실제 필요 시 추가)
- Dashboard 탭 (자동 KPI 집계)
- 산출물 체크리스트 탭 (9종+ 진척도 자동 계산)
- 주간보고 빌더 탭 (Google Docs 텍스트 자동 추출)
- GAS 알림 자동화 (마감 임박 D-3 Slack)
- 워크숍 일정 분리 탭 (탭2 셀 주석으로 부족할 때)

> **원칙**: Phase 1(5개 탭)을 시범 운영하면서 진짜 필요한 항목만 추가. "있으면 좋은 것"은 추가하지 않음.

## 9. 산출물 폴더 골격 (★ 추가 요구사항, v0.2 단순화)

### 9.1 설계 원칙
- **단순함 우선**: 폴더는 M·S 단위까지만. 그 안의 파일 구성은 컨설턴트 자유.
- **공유양식은 00, 기업은 01~08** (가나다순, 메모리 넘버링 그대로 통일)
- 각 S 폴더에 컨설턴트가 **최종 결과물 파일들을 직접 업로드** (예: W/S 진행자료 PPT, W/S 결과 파일, 회의 사진 묶음 등)
- 작업 중간본 격리(_WIP) 같은 부가 규칙은 두지 않음 — 컨설턴트 재량
- 한글 폴더명 그대로. 슬래시(/)만 가운뎃점(·)으로 (`W/S` → `W·S`)

### 9.4 파일명 권장 (선택)
- 자유롭게 작성하되, 의미가 분명하면 OK
- 최종본임을 표시하고 싶을 때만 `_FINAL` 또는 날짜 접미사 권장 (예: `요구분석_결과_260520.docx`)
- 강제 컨벤션 없음

### 9.5 프로젝트 성과관리 시트 연동
- 프로젝트 성과관리 시트 탭9(산출물 체크리스트)의 "납품파일 링크" 컬럼이 이 폴더의 파일을 가리킴
- 컨설턴트가 파일 업로드 후 프로젝트 성과관리 시트에 링크만 추가하면 추적 가능

### 9.6 즉시 생성 vs 단계별 생성

- **옵션 A (즉시 풀세트 생성, 추천)**: 약 101개 폴더 한 번에 mkdir. 컨설턴트들이 시작부터 일관된 구조 사용
- **옵션 B (단계별 생성)**: M1 폴더만 우선 생성, M2~M5는 해당 단계 진입 시 생성
- **옵션 C (기업별 진입 시)**: 기업 사업 착수 시 해당 기업 폴더 풀 트리 생성

> 본 설계안은 옵션 A를 추천. 사용자 확정 후 mkdir 1회 실행으로 골격 완성 (약 5분).
