# 🤖 카톡 → 시트 AI 자동화 워크플로 v1

> **사령탑 1인 입력 병목**(v2 약점 5번)의 해결책.
> 매주 일요일 30~60분 → **AI와 함께 10~15분**으로 단축.

---

## 1. 무엇이 자동화되나

### 자동화 전 (v2)
1. 가족 카톡 다시 훑기 (10분)
2. 메시지를 한 줄씩 운영기록부 시트에 손으로 입력 (20~40분)
3. 거래처·SKU 정보 매번 손으로 확인 (10분)

### 자동화 후 (v4 + AI)
1. **카톡 메시지를 그대로 AI에게 붙여넣기** (1분)
2. **AI가 시트 행으로 자동 변환** (3분 — AI가 처리)
3. **사령탑은 검토 후 시트에 한 번에 붙여넣기** (5분)

---

## 2. 사령탑 표준 프롬프트 (복사·붙여넣기용)

매주 일요일 새 채팅 시작 시 다음을 그대로 붙여넣기:

```
[사령탑이 카톡 → 시트 자동화 요청]

다음은 이번 주 가족 단톡 메시지입니다.
운영기록부 v4의 적절한 시트로 변환해서 행 단위로 정리해주세요.

규칙:
1. 어머니·아버지·태균이 메시지는 모두 평등하게 처리
2. 모호한 정보는 [확인 필요]로 표시
3. 거래처 이름이 나오면 M2에서 ID 찾고, 없으면 신규 등록 제안
4. SKU 이름이 나오면 M1 ID로 변환 (예: "약주 375" → WG-YJ-375)
5. 시트별로 분리해서 출력 (01·02·03·05·06·07 중 해당)
6. 행마다 일자·자동 컬럼은 비워두고 입력 필요한 것만

[이번 주 카톡 (날짜·발신자 포함해서 그대로 붙여넣기)]
어머니 5/10 오전: 찹쌀 50kg 들어왔어, 대농 김씨네서 22만원
아버지 5/12 오후: 누룩 깨움. 약주 새 배치 시작.
어머니 5/14 저녁: 손님 다녀가셨어, 약주 2병 5만원
아버지 5/16 오전: 약주 거름 끝. 187L 나옴.
어머니 5/17 오후: 주박 30kg 나옴
어머니 5/20: 새 약주 시음했어, 단맛 더 단정함

위 메시지를 v4 운영기록부 시트별로 변환해주세요.
```

## 3. AI 응답 형식 (사령탑 검토용)

AI는 다음 형식으로 답변합니다:

```
## 01_원료수불부 (1행 추가)

| 일자       | 구분       | 품목 | 수량 | 단가   | 금액   | 거래처ID | 비고               |
|------------|-----------|------|------|--------|--------|----------|--------------------|
| 2026-05-10 | 입고(원료) | 찹쌀 | 50.0 | 4,400  | 220,000| V-001    | 대농 김씨네        |

## 02_양조일지 (1행 추가)

| 담금일     | 배치ID       | 주종 | 1차술덧 | 최종생산량 | 도수 | 사용원료                          |
|------------|--------------|------|---------|-----------|------|-----------------------------------|
| 2026-05-12 | 2026Q2-002   | 약주 |         | 125.0     | 15   | [확인 필요 — 5/16 거름 187L는 탁주? 약주?] |

⚠️ 확인 필요: 약주는 일반적으로 1배치 125L. "약주 거름 187L"는 탁주일 가능성. 아버지께 확인 권장.

## 03_출고판매기록 (1행 추가)

| 반출일     | 채널         | 거래처ID | SKU ID     | 수량 | 단가   | 금액   |
|------------|--------------|----------|------------|------|--------|--------|
| 2026-05-14 | 양조장직판   | C-???    | WG-YJ-375  | 2    | 25,000 | 50,000 |

⚠️ 거래처ID 확인: "손님"이 단골인지 신규인지 모름. C-XXX 부여 권장.

## 05_부산물폐기 (1행 추가)

| 일자       | 부산물 종류 | 수량 | 단위 | 처리방식      | 관련 배치ID |
|------------|------------|------|------|--------------|-------------|
| 2026-05-17 | 주박(약주) | 30.0 | kg   | [확인 필요]   | 2026Q2-002  |

## 06_시음QC (1행 추가)

| 일자       | 구분       | 배치ID       | 향 | 맛 | 바디 | 균형 | 여운 | 종합 | 메모                |
|------------|-----------|--------------|----|----|------|------|------|------|---------------------|
| 2026-05-20 | 시음(가족) | 2026Q2-002   | [?] | [?] | [?] | [?] | [?] | (자동) | 단맛 더 단정함     |

⚠️ 시음 5점 척도 비어있음. 다음 통화 때 아버지께 점수 여쭙기 권장.

## 다음 액션
1. ⚠️ 5/16 "약주 거름 187L"가 탁주인지 약주인지 아버지께 확인
2. ⚠️ 단골 손님 신규 등록 → C-XXX 부여
3. ⚠️ 시음 5점 척도 입력 (다음 통화)
4. 위 행들을 v4 시트에 복사·붙여넣기
```

## 4. 사령탑 검토 체크리스트

AI 응답을 받으면 다음을 점검:

- [ ] **사실 검증** — 날짜·수량·이름 모두 카톡과 일치하는가?
- [ ] **[확인 필요] 항목** — 다음 통화 때 부모님께 여쭤볼 것들
- [ ] **거래처ID 매칭** — 모르는 거래처는 M2에 먼저 등록
- [ ] **시트별 복사** — AI가 정리한 표를 각 시트에 행 단위로

검증 통과 후 시트에 붙여넣기.

## 5. AI 호출 빈도 권장

| 빈도 | 처리량 | 권장 시점 |
|------|--------|----------|
| **매주 일요일** ★ | 한 주 분량 (10~30 메시지) | 일요일 저녁 |
| **매일** | 그날 분량 (1~5 메시지) | 너무 자주, 권장 X |
| **격주** | 두 주 분량 (20~60 메시지) | 시간 부족할 때만 |
| **월 1회** | 한 달 분량 | 누락 위험 큼, 비권장 |

**권장: 매주 일요일 저녁 30분.**

## 6. 빠진 정보 보완 패턴

### 패턴 A — 메시지에 일자가 없을 때
AI가 "[일자 추정: 2026-05-XX (전후 메시지 기반)]"로 표시
→ 사령탑이 확인 후 확정

### 패턴 B — 금액·수량이 모호할 때
AI가 "[금액 ?만원 추정]"로 표시
→ 부모님께 다음 통화 때 확인

### 패턴 C — 거래처가 처음 나올 때
AI가 "[신규 거래처 등록 필요]"로 표시
→ M2에 먼저 등록 후 ID 부여

### 패턴 D — SKU 약칭만 있을 때
AI가 약칭("약주" → "WG-YJ-375")로 자동 변환
→ 사령탑이 확인 (잘못된 추론 가능성 점검)

## 7. 5가지 카톡 입력 패턴과 자동화

가족이 외운 [카톡 입력 5문장](../00_시작하기/07_카톡_입력_5문장_인쇄용.docx)을 따르면 AI 정리가 더 정확해집니다.

| 카톡 패턴 | 변환 시트 | 자동화 성공률 |
|-----------|----------|--------------|
| 원료 입고 (날짜·품목·수량·매입처·금액) | 01_원료수불부 | 95% |
| 양조 단계 + 사진 | 02_양조일지 | 90% (단계 추론) |
| 출고·판매 (날짜·SKU·수량·가격) | 03_출고판매 | 95% |
| 월말 재고 | 04_재고관리 | 90% |
| 시음 후기 | 06_시음QC | 70% (5점 척도 별도 입력) |

## 8. 한계와 주의사항

### AI가 잘 못하는 것
- **음성 메시지** — 텍스트로 받아쓰기는 사령탑이 직접
- **사진 안의 정보** — 사진은 사령탑이 보고 텍스트로 묘사 후 AI에 전달
- **모호한 표현** — "한 모금" → 정량 입력 불가, 사령탑 보정

### 검증 책임
- AI 출력은 **초안**. 시트에 들어가는 최종 책임은 사령탑.
- 특히 **세금계산서 번호·도수·일자** 등은 100% 직접 확인.
- 거래처 ID 매칭이 잘못되면 → 잘못된 인적사항이 기록될 수 있음

## 9. 미래 확장 — Apps Script 자동 import

5년 후 데이터가 충분히 쌓이면 다음 자동화 검토:

- 카드결제 데이터 import
