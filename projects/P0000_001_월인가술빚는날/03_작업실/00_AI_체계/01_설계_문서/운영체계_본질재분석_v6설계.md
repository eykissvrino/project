# 🔬 운영 기록 체계 — 본질 재분석 (v6 설계)

> 사용자 요청: **"법적 + 체계적 + 효율적 + 효과적"** 네 가지를 한 번에.
>
> v4·v5를 모두 만들어본 후, 한 단계 더 깊이 들어간 결론.

---

## 1. 사용자 질문의 재해석 — "네 가지 동시 충족"이 모순 같아 보였던 이유

### 표면적 모순
| 요건 | v4(15시트) | v5(5시트) |
|------|-----------|----------|
| 법적 완전성 | 🟢 챙김 | 🟡 빈틈 |
| 체계성 | 🟢 강함 | 🟡 약함 |
| 효율성 | 🔴 부담 큼 | 🟢 매우 좋음 |
| 효과성(가족이 실제 씀) | 🔴 안 씀 | 🟢 씀 |

> v4와 v5는 마치 **트레이드오프**처럼 보였다. 더 법적이면 더 복잡, 더 단순하면 더 빈틈.

### 그런데 — 정말 트레이드오프인가?

이 질문이 본질입니다. **"하나의 시트에 법적 정보를 다 담아야 한다"는 가정 자체가 틀렸을 수도 있다.**

---

## 2. 가정 점검 — "운영기록부에 모든 게 들어가야 한다"는 정말 맞나?

### 법령을 다시 읽어보면

**주류 면허법 시행령 §25:** "주류제조자는 다음 사항을 **장부에 기록**해야 한다 — 인도인·수취인 인적사항 등"

여기서 핵심 단어 두 개:
- **"장부"** — 어떤 형태든 OK (종이·전자·외부 시스템)
- **"기록"** — 어디든 보존되어 있으면 OK

법령은 "운영기록부 엑셀 한 파일에 다 적어라"라 하지 않습니다. **"기록이 어딘가에 있으면 된다"** 는 의미예요.

### 실제 양조장이 어떻게 하는지 (실무 관행)

세 가지 거래 유형에 따라 인적사항 보존 방식이 **자연스럽게 다릅니다**:

| 거래 유형 | 인적사항이 어디에 보존되나 | 운영기록부 역할 |
|-----------|--------------------------|----------------|
| **B2B 도매** (레스토랑·바틀샵) | **전자세금계산서** (홈택스 자동 보존) | 거래 발생 사실만 기록 |
| **양조장 직판** (방문 손님) | **카드 매출전표·현금영수증** (PG사·카드사 자동 보존) | 매출 합계만 기록 |
| **통신판매** (스마트스토어) | **주문 시스템** (네이버 자동 보존) | 주문 건수·합계만 기록 |
| **체험·시음회** (개인정보 수집) | **별도 동의서 + 마스킹 명단** | 행사 기록만 |

> 💡 **인적사항은 이미 세 곳에 자동 보존되고 있습니다.** 운영기록부가 또 한 번 받을 필요가 없어요.

### 실무에서 운영기록부의 진짜 역할

운영기록부는 **흐름 파악**이고, **인적사항 보관소**가 아닙니다.

- "이 분기에 매출이 얼마였나?" → 운영기록부
- "5월 14일 약주 2병을 누가 사갔나?" → **카드사·현금영수증·POS** (운영기록부가 아님)
- "○○ 한식당에 사계주 10병 보낸 게 맞나?" → **세금계산서** (운영기록부는 단지 cross-check)

## 3. 인사이트 — 책임 분리 (Separation of Concerns)

### 깨달음

> 법적 의무를 **하나의 시트가 다 짊어질 필요가 없다.**
> 각 시스템이 **자기가 잘하는 일을 분담**하면 된다.

### 시스템별 책임

| 시스템 | 책임 | 사용자 부담 |
|--------|------|------------|
| **홈택스 전자세금계산서** | B2B 인적사항·금액 보존 | 도매 거래 시 발행 (분기 몇 건) |
| **카드 단말기 or PG사** | 직판 매출·결제 정보 보존 | 자동 |
| **현금영수증 시스템** | 현금 거래 매출 보존 | 손님 요청 시 발급 |
| **스마트스토어** | 통신판매 주문·인적사항 보존 | 자동 |
| **운영기록부 (v5)** | 매일의 흐름·재고·양조 일지 | 한 줄 입력 |
| **사령탑·AI** | 분기마다 위 모든 곳 매칭·통합 | 분기 1회 |

### 핵심 통찰

> "운영기록부를 복잡하게 만드는 게 아니라, **각 시스템이 자기 일을 하게 두고 사령탑이 분기마다 통합**하면 된다."

---

## 4. 3-Layer 운영 체계 (v6 설계)

```
┌──────────────────────────────────────────────────────────┐
│ Layer 3 — 분기 통합 (사령탑 + AI)              [분기 1회] │
│                                                            │
│  · 홈택스에서 분기 세금계산서 다운로드                      │
│  · 카드사·PG사 매출 명세 다운로드                          │
│  · 스마트스토어 주문 데이터 다운로드                       │
│  · v5 운영기록부 분기 합계와 매칭                           │
│  · 차이·누락 보완 → 주세 신고                              │
└──────────────────────────────────────────────────────────┘
                            ▲
                            │ 매칭·통합
                            │
        ┌───────────────────┴─────────────────────┐
        │                                          │
        ▼                                          ▼
┌──────────────────────┐         ┌──────────────────────────┐
│ Layer 2              │         │ Layer 1                  │
│ 외부 시스템 (자동)    │         │ 운영기록부 v5 (일상)      │
│                      │         │                          │
│ · 전자세금계산서      │         │ · 01_매일_기록 (한 줄)   │
│   (홈택스)           │         │ · 02_거래처 (B2B만)      │
│ · 카드 매출전표      │         │ · 03_월말 재고            │
│   (POS·PG사)         │         │ · 04_분기_정리 (자동 합계)│
│ · 현금영수증         │         │                          │
│   (국세청)           │         │                          │
│ · 스마트스토어 주문   │         │                          │
│   (네이버)           │         │                          │
└──────────────────────┘         └──────────────────────────┘
        ▲                                          ▲
        │ 거래 즉시·자동                              │ 매일·한 줄 입력
        │                                          │
        ◯ 손님 결제                              ◯ 손님 응대 후 사령탑
```

### Layer별 역할

#### Layer 1: 운영기록부 v5 (매일)
- 양조장 스마트폰에 띄워 한 줄씩
- 부담 0, 양조장 현장 친화
- 매출·양조·재고 흐름 파악

#### Layer 2: 외부 시스템 (거래 즉시·자동)
- **이미 사용 중**일 가능성 큼 (카드 단말기·홈택스·스마트스토어)
- 거래 즉시 자동 보존 → 사람이 따로 입력 X
- 법적 인적사항은 여기에 자동 누적

#### Layer 3: 분기 통합 (사령탑 + AI)
- 분기 1회, 1~2시간
- AI가 외부 시스템 데이터를 v5와 매칭
- 차이·누락 보완 후 주세 신고

## 5. 이 체계의 장점 — 네 가지 요건 모두 충족

| 요건 | v4 단독 | v5 단독 | v6(3-Layer) |
|------|---------|---------|-------------|
| **법적** | 🟢 시트 안에서 챙김 (어색) | 🟡 빈틈 있음 | 🟢 외부 시스템 + 분기 매칭으로 완전 |
| **체계적** | 🟢 강함 (15시트) | 🟡 약함 | 🟢 책임 분리가 진짜 체계 |
| **효율적** | 🔴 매일 부담 큼 | 🟢 매우 좋음 | 🟢 v5 + 분기 1회만 |
| **효과적** | 🔴 안 씀 | 🟢 씀 | 🟢 매일은 v5 그대로 |

## 6. v6의 구체 구현 — v5에 무엇만 추가하면 되나?

**v5를 갈아엎지 않습니다.** v5 + 두 가지 추가만:

### A. v5 운영기록부에 추가할 컬럼 1개
- 04_분기_정리 시트에 "**외부 시스템 매칭**" 컬럼 추가
- 분기마다 사령탑이 ✓ 표시 (홈택스·POS·스마트스토어와 합산이 일치하는지)

### B. 분기 통합 매뉴얼 1쪽
- 사령탑이 분기 1회 따라하는 절차
- 홈택스·POS·스마트스토어에서 무엇을 다운로드
- v5와 어떻게 매칭
- 차이가 있으면 어떻게 보완

### C. 연간 법적 의무 캘린더 (1쪽)
- 분기 신고(4·7·10·1월 25일)
- 자가품질검사(6개월 1회)
- 면허 갱신·농업경영체 자격(연 1회)
- 한 화면에 다 보임

**= 총 추가물 3개. 매뉴얼 2쪽 + 시트 컬럼 1개. 그게 다.**

## 7. 사용자 일상 — 무엇이 달라지나?

### 어머니·아버지·태균이
**아무것도 안 달라집니다.** 평소처럼 카톡·통화·종이.

### 사령탑(이석주)
- **매일·매주:** v5 그대로. 카톡 → 한 줄 입력. 10~15분/주.
- **매월:** 04_재고 마감. 5분.
- **분기 1회:** 분기 통합 매뉴얼 따라 1~2시간 → 주세 신고.
- **연 1회:** 면허·농업경영체 자격 갱신.

### AI 팀
- **콘텐츠 디렉터·전략 파트너:** v5 데이터 그대로 활용.
- **행정 매니저:** 분기 1회 사령탑과 함께 외부 시스템 매칭·신고서 초안 자동 생성.
- **재무 매니저:** 04_분기_정리 + Layer 2 합산으로 KPI 보고.

## 8. 한 줄 결론

> **운영기록부 하나에 법적 완전성을 다 욱여넣으려는 시도 자체가 잘못된 출발이었습니다.**
> 양조장은 이미 홈택스·카드사·스마트스토어라는 **법적 보존 시스템**을 쓰고 있습니다.
> v5는 매일의 흐름만 잡고, 사령탑이 분기에 한 번 모든 시스템을 묶어주는 **3-Layer 체계**가
> "법적 + 체계적 + 효율적 + 효과적" 네 가지를 모두 만족시키는 진짜 답입니다.
