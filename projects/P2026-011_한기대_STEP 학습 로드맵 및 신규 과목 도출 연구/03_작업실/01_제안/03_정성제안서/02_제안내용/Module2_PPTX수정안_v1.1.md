# Module 2 (NCS 세분류 우선순위 도출) — PPTX 6장 수정안 v1.1

## 톤 정정 사항 (v1.0 → v1.1)

> **시앤피컨설팅이 2025·2026 양 사업의 수행 파트너이므로 외부 비교 톤을 자기 발전 스토리로 정정**

| v1.0 표현 (폐기) | v1.1 표현 (채택) |
|---|---|
| 시앤피 2025 vs 우리 2026 | **AS-IS('25 적용) → TO-BE('26 개선)** |
| 시앤피 한계 → 우리 해법 | **작년 한계 → RFP 권고 반영 → 올해 개선** |
| 시앤피 9.5% → 우리 25%+ | **'25 응답률 9.5%의 한계를 보완하여 '26 25%+ 목표** |
| 차별점 박스 (외부 비교) | **개선점 박스 (자기 발전 + 트레이드오프 노출)** |

### 사용자 권고 형식 (전체 6장 일관 적용)

> "기존에는 ~~~ 였는데, 이렇게 했을 때 [이슈 및 문제점]들을 보완하기 위해 RFP 내용처럼 ~~~ 하려고 한다. 이렇게 했을 때 [단점]은 안 좋지만 [기대효과]가 있다."

## 슬라이드 ② (PPTX p.16) — Step 3 둘째 장: 수요평가 지표 체계 ★ 비중 재정리

### 헤드 박스
```
Step 3 │ Q. 정량·정성·설문 평가지표를 RFP 명시 비율(50/35/15)에 맞춰 어떻게 재구성할 것인가?
```

### 카피 메시지 ★
> **'25 적용 시 정량 70 : 정성 30 = 100점 구조**를 RFP §II-2 명시 비율을 정확히 반영하여 **설문 50 + 정량 35 + 정성 15 = 100점** 구조로 재구성하고, 정량 11지표·정성 3지표는 각각 100점 내부 정규화 후 RFP 비율 가중을 적용

### AS-IS → TO-BE 흐름 박스 (상단, 강조)

```
┌─────────────────────────────────────────────────────────────────────────┐
│  ▸ AS-IS ('25 적용 방식)                                                  │
│    정량 11지표 합 ≈ 70점 + 정성 3지표 합 = 30점 = 100점                   │
│    + 설문 100점 별도 합산 → 총 200점 만점                                 │
│    한계: ① 설문 비중이 RFP §II-2 명시 비율과 정합 약함                     │
│         ② 정량·정성 통합이 정량 우위 → 미래 시점·전문가 정성 약화           │
│                                                                          │
│  ▸ TO-BE ('26 개선) — RFP 명시 비율 정확 적용                              │
│    설문 50% + 정량 35% + 정성 15% = 100점                                 │
│    기대효과: ① RFP §II-2 정합성 확보                                        │
│             ② 학습자·기업 수요(설문)를 최우선 반영                          │
│             ③ 정량·정성 분리 정규화로 미래 시점 지표(정성) 가시화           │
└─────────────────────────────────────────────────────────────────────────┘
```

## 슬라이드 ③ (PPTX p.17) — Step 3 셋째 장: 수요조사(설문) — 시나리오 B 재배치 ★

> **사용자 권고 형식 모범 사례 슬라이드 — 자기 발전 + 트레이드오프 정직 노출**

### 헤드 박스
```
Step 3 │ Q. 설문 단계를 RFP [조사체계 개선] 권고대로 어떻게 재배치하고 응답률·신뢰성을 어떻게 끌어올릴 것인가?
```

### 카피 메시지 ★ — AS-IS → 문제점 → 개선 방향 → 트레이드오프

> **기존('25 적용)**에는 능력단위 선정 → 과목 도출 → 설문조사 순서로 진행했으나, 설문이 후행 단계에 위치하여 ① 응답률 9.5%의 한계 ② 세분류 단계 수요가 능력단위 도출 과정에 직접 반영되지 않는 한계가 있었음. 이를 **RFP §II-3 [조사체계 개선] 권고**대로 **세분류 단계에서 설문을 통합 진행(시나리오 B)** 하고자 함.

### 본문 — 트레이드오프 박스 (단점과 기대효과 정직 노출) ★ 사용자 권고 형식

```
┌──────────────────────────────────────────────────────────────────────────┐
│                                                                          │
│  ▸ AS-IS ('25 적용 흐름)                                                   │
│    능력단위 선정  →  과목 도출  →  설문조사                                 │
│                                                                          │
│  ▸ AS-IS 이슈 및 문제점                                                    │
│    ① 응답률 9.5%의 한계 (설문 후행 배치로 인한 응답 피로 누적)              │
│    ② 세분류 우선순위 산정에 학습자·기업·기관 수요 미반영                    │
│    ③ 응답 부담 큰 능력단위 단위 설문 → 결과 활용도 저하                     │
│    ④ 분야별 균형 잡힌 수요 청취 어려움                                      │
│                                                                          │
│  ▸ TO-BE ('26 개선 흐름) — RFP §II-3 [조사체계 개선] 직접 답                  │
│    세분류 우선순위 + 설문조사 동시 진행  →  능력단위 선정  →  과목 도출      │
│                                                                          │
│  ▸ 단점 (정직 노출)                                                        │
│    ① 능력단위 단위 세부 수요 정보는 별도 수집 필요                          │
│       → Module 3 정성 평가 3지표(수요·필요성·시급성)로 보완                  │
│    ② 240개 세분류 × 응답자 → 표본 분산 가능성                              │
│       → 응답자 가중치 모델(직무·산업·경력별)로 편향 자동 보정               │
│                                                                          │
│  ▸ 기대효과                                                                │
│    ① 응답 부담 감소로 응답률 향상 (9.5% → 25%+ 목표, 2.6배 향상)            │
│    ② 세분류 우선순위에 학습자·기업·기관 수요 직접 반영                      │
│    ③ 후행 단계(능력단위·과목)의 신뢰성 향상                                  │
│    ④ RFP §II-3 [조사] 4대 제언 정직한 답 → RFP 충실 시그널 강화              │
│    ⑤ 27년 상시 운영 모델 확장 시 세분류 단위가 모집단 분포에 적합            │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```
