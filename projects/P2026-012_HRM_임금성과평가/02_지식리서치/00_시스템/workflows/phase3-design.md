# Phase 3: To-Be 설계

## 목적
진단에서 도출된 이슈를 해결하는 신제도를 설계하고, 시뮬레이션·검증을 거쳐
확정한다.

## 주요 활동

### 3.1 설계 원칙 확정
- 진단 결과 → 설계 방향성 정의
- 설계 원칙 합의 (스폰서·임원)
- 옵션 비교 (3안 정도)

### 3.2 상세 설계
- 영역별 설계 스킬 활용:
  - 임금: `pay-structure-design`
  - 평가/성과: `performance-system-design`
  - 직무평가: `job-evaluation`
  - 역량: `competency-modeling`
  - 조직: `org-design`
  - JD: `jd-development`
- 설계 결과물 (제도 설계서)

### 3.3 시뮬레이션
- 개인별 영향 시뮬레이션 (임금/평가)
- 조직 차원 영향 (인건비, 평가 분포)
- `hr-toolkit-build` 스킬로 엑셀 모델 구축

### 3.4 검증
- 법적 검토 (`labor-law-expert`)
  - 통상임금·취업규칙 변경
  - 노조 단협 영향
- 노조 사전 협의 (해당 시)
- 클라이언트 인사위원회 검토
- 파일럿 검토 (선택)

### 3.5 확정·보고
- 설계 최종안 확정
- 중간/최종 보고
- 의사결정 (Steering Committee)

## 체크리스트

- [ ] 진단 결과와 설계 방향성이 연계되는가
- [ ] 옵션 비교 (Pros/Cons)가 충분한가
- [ ] 개인별·조직 차원 영향이 시뮬레이션되었는가
- [ ] 법적 리스크가 검토되었는가
- [ ] 이행기(Pay Protection 등) 옵션이 포함되었는가
- [ ] 설계서가 실무자가 운영 가능한 수준인가
- [ ] 의사결정자(임원/노조)의 수용 가능성이 검토되었는가
