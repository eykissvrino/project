# SKILL: Consulting Report (컨설팅 보고서 작성)

## 목적
McKinsey/BCG급 컨설팅 보고서를 Pyramid Principle 기반으로 작성한다.
의사결정자가 핵심을 빠르게 파악하고 실행에 옮길 수 있도록 한다.

## 트리거
- "보고서 작성", "Report 작성"
- "진단 보고서", "설계 보고서", "최종 보고서"
- "임원 보고", "착수 보고", "중간 보고", "최종 보고"

## 사전 입력 (Inputs)

| 필수/선택 | 항목 |
|-----------|------|
| 필수 | 보고서 목적 (진단/설계/Status/최종) |
| 필수 | 핵심 메시지 (1~3개) |
| 필수 | 분석·설계 결과물 |
| 필수 | 보고 대상 (CEO/임원/실무자) |
| 권장 | 보고 시간 (10분 / 30분 / 1시간) |
| 권장 | 보고 형식 (PPT / Word / Excel) |

## 표준 워크플로우

### Step 1. 보고 목적·청중 분석
- **무엇을 결정/실행하게 하려는가?**
  - 단순 정보 공유 X
  - 의사결정 유도 (안 A vs B 선택)
  - 실행 동의 획득
  - 추가 자원 요청
- **청중 분석**:
  - C-Level: 결론 위주, Why·How 핵심
  - 실무자: 디테일 풍부, 운영 가능성
  - 노조: 영향 투명, 근거 명확

### Step 2. 핵심 메시지 정의 (Top of Pyramid)
- **1줄 메시지 ("So What?")**:
  - 모든 분석을 관통하는 단 하나의 결론
  - 예: "현행 호봉제는 성과주의 전환의 가장 큰 장애물이며, 직무급 단계적 도입이 필요함"
- 보고서 전체를 이 한 줄로 압축 가능해야 함

### Step 3. 스토리라인 설계 (SCQA)

#### SCQA Framework
- **S(Situation)**: 현재 상황 (모두가 동의하는 사실)
- **C(Complication)**: 그러나 문제가 발생 (변화/위협/기회)
- **Q(Question)**: 따라서 답해야 할 질문
- **A(Answer)**: 그 답이 곧 보고서의 결론

#### Pyramid Structure
```
                  [Top Message]
                       │
        ┌──────────────┼──────────────┐
   [Key Line 1]   [Key Line 2]   [Key Line 3]
        │              │              │
    [근거들]        [근거들]        [근거들]
```
- Key Line 3개 (MECE 원칙)
- 각 Key Line 아래 2~4개 근거

### Step 4. 목차 설계

#### 표준 진단 보고서 목차
```
1. Executive Summary (2~3p)
2. 추진 배경 및 목적
3. 진단 접근 방법
4. 주요 발견사항 (Key Findings)
   4.1 [발견 1: 핵심 메시지]
   4.2 [발견 2: 핵심 메시지]
   ...
5. 시사점 및 권고사항
6. 향후 추진 방향
[Appendix]
A. 인터뷰 리스트
B. 데이터 상세
C. 벤치마크 자료
```

#### 표준 설계 보고서 목차
```
1. Executive Summary
2. 설계 배경 및 원칙
3. 제도 개요 (한 장 요약)
4. 상세 설계
   4.1 [영역 1]
   4.2 [영역 2]
   ...
5. 시뮬레이션 결과 (영향 분석)
6. 운영 방안 (R&R, 일정)
7. 이행 계획
8. 기대효과 및 리스크
[Appendix]
```

### Step 5. 슬라이드 작성 (PPT 기준)

#### Slide Anatomy
```
┌────────────────────────────────────────────┐
│ [Slide Title - 결론 메시지 1문장]            │  ← Header (가장 중요)
├────────────────────────────────────────────┤
│                                            │
│   [Body - 차트/표/다이어그램]               │
│                                            │
├────────────────────────────────────────────┤
│ Source: ...                  P.XX / Date   │  ← Footer
└────────────────────────────────────────────┘
```

#### 슬라이드 원칙
- **1 Slide 1 Message**: 한 슬라이드 한 메시지
- **Title = Conclusion**: 제목이 결론 (예: "성과제도는 운영 부담이 과중함"
  → "X" 형식. "성과제도 진단 결과" → 의미 약함)
- **Visual 우선**: 텍스트보다 표·차트·다이어그램
- **Top to Bottom 읽기**: 왼쪽 위에서 오른쪽 아래로 자연 흐름

#### Visual 선택
| 목적 | 적합한 Visual |
|------|--------------|
| 트렌드 | Line, Area |
| 비교 | Bar, Grouped Bar |
| 분포 | Box Plot, Histogram |
| 비중 | Stacked Bar (>5 항목), Donut/Pie (<5) |
| 다차원 | Heat Map, Bubble |
| 프로세스 | Flow, Swimlane |
| 매트릭스 | 2×2, 3×3 Matrix |
| 우선순위 | Impact-Urgency 매트릭스 |

### Step 6. Executive Summary 작성 (필수)
- 분량: 2~3 페이지 (또는 슬라이드 3~5장)
- 구성:
  - 추진 배경 (3~5줄)
  - 핵심 발견 (Top 5)
  - 권고사항 (Top 3)
  - 기대효과
- **단독으로 읽혀 의사결정 가능해야 함**

### Step 7. 자체 검증
- [ ] 첫 페이지만 읽고 핵심 파악 가능한가
- [ ] 각 슬라이드 Title이 결론인가
- [ ] MECE인가 (중복 X, 누락 X)
- [ ] 모든 숫자에 출처가 있는가
- [ ] 권고사항이 실행 가능한가 (Who, What, When)
- [ ] Pages가 적절한가 (보고시간 / 2분 = 슬라이드 수)

### Step 8. 클라이언트 리뷰·수정
- 핵심 인사이트 vs 잘못 해석된 부분 확인
- 정치적·민감 표현 조정 (객관 유지하되 톤 부드럽게)
- 익명 처리 재확인 (인터뷰 인용)

## 산출물 (Outputs)

1. **컨설팅 보고서 본문** (PPT 또는 Word)
2. **Executive Summary** (별도 1~2페이지 가능)
3. **Appendix** (분석 데이터, 인터뷰 리스트)

## 품질 체크리스트

- [ ] 핵심 메시지가 1줄로 요약되는가
- [ ] 슬라이드 Title이 모두 결론형인가
- [ ] Pyramid (Top → Key Lines → Detail) 구조가 명확한가
- [ ] Executive Summary 단독으로 의사결정 가능한가
- [ ] 모든 데이터에 출처·시점이 있는가
- [ ] Visual Element가 충분한가 (텍스트만 슬라이드 최소화)
- [ ] 권고사항이 실행 가능한가
- [ ] 청중에 맞는 분량·수준인가
