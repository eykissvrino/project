## 4. 작업 시작 시 표준 절차

1. **사용자 요청 파악**: 어떤 HR 영역의 어떤 작업인지 분류
2. **관련 에이전트 확인**: `00_시스템/agents/` 중 해당 영역 전문가 호출
3. **관련 스킬 확인**: `00_시스템/skills/` 중 해당 작업 워크플로우 적용
4. **지식베이스 참조**: `01_지식베이스/` 에서 방법론·법규 확인
5. **템플릿 활용**: `02_템플릿/` 에서 산출물 양식 가져와 시작
6. **프로젝트 폴더 사용**: 산출물은 `03_프로젝트/[해당프로젝트]/` 에 저장

## 7. 산출물 작성 원칙

### 7.1 공통 원칙
- **한글 기본**, 전문용어는 영문 병기 (예: 직무평가(Job Evaluation))
- **3-Tier 구조**: Executive Summary → Body → Appendix
- **데이터 기반**: 주장에는 근거(벤치마크/시장정보/사례) 첨부
- **실행 가능성**: "무엇을 어떻게" 까지 구체화

### 7.2 보고서 톤
- 컨설턴트적 어조 (객관·분석적·논리적)
- 단정형 결론 + 근거 명시
- 시각화 우선 (표·차트·매트릭스)

### 7.3 파일 명명 규칙
```
[YYMMDD]_[클라이언트약칭]_[산출물유형]_v[버전].확장자
예: 260513_ABC상사_임금체계진단보고서_v1.0.docx
    260513_ABC상사_직무평가툴킷_v0.3.xlsx
```

## 8. 컨설팅 단계별 표준 흐름

```
[1단계: Kickoff]      → 제안서, 착수보고서, 프로젝트 계획
[2단계: As-Is 진단]   → 현황 분석, 인터뷰, 갭 분석
[3단계: To-Be 설계]   → 제도 설계, 시뮬레이션, 검증
[4단계: 실행 지원]    → 매뉴얼, 변화관리, 교육자료
[5단계: 안착 점검]    → 운영 점검, 보완, 최종 보고
```

각 단계의 표준 산출물 및 체크리스트는 `00_시스템/workflows/` 참조.

## 9. 사용자 협업 원칙

- **모든 응답은 한글로 작성**
- 모호한 요청은 명확화 질문 (AskUserQuestion 활용)
- 작업 전 관련 메모리(`memory/`), 에이전트, 스킬 정의 확인
- 새로운 인사이트·케이스는 `01_지식베이스/` 에 축적
- 산출물은 항상 `03_프로젝트/` 또는 워크스페이스 루트에 저장하여 사용자가 즉시 접근 가능하도록
