# AI 에이전트 활용 전략서

## 직업정보 프레임워크 연구 — AI 전방위 활용 전략

---

## 1. AI 활용 철학

본 프로젝트에서 AI(Claude)는 단순 도구가 아니라 **"세 번째 연구원"**이다. 2인 코어팀(조세형 PI + 이석주 실무총괄)이 8개월간 6명분의 연구를 수행하기 위해, AI가 데이터 수집부터 분석·작성·검증까지 전 과정에 참여한다.

## 3. 커스텀 스킬 목록

### 3.1 pm-dashboard (프로젝트 관리)
- **위치**: `.claude/skills/pm-dashboard/`
- **역할**: 마일스톤 관리, 주간 할일 생성, 진행률 추적, 보고회 준비 상태 점검
- **트리거**: "진행상황", "이번주 뭐해야해", "보고회 언제"
- **연구 단계**: 전 기간 상시 가동

### 3.2 ksco-data-collector (데이터 수집)
- **위치**: `.claude/skills/ksco-data-collector/`
- **역할**: KSCO, KECO, 워크피디아, 한국직업사전, O*NET 데이터 수집·정제
- **트리거**: "데이터 수집", "크롤링", "직업데이터"
- **연구 단계**: M+1~2 집중, 이후 보완 수집
- **출력**: CSV/JSON 정제 데이터셋

### 3.3 nlp-job-analyzer (NLP 직무분석) ⭐ 핵심
- **위치**: `.claude/skills/nlp-job-analyzer/`
- **역할**: 직업설명 텍스트→직무활동 추출→표준화 직무요소 구조화
- **트리거**: "직무분석", "텍스트분석", "직무활동 추출"
- **연구 단계**: M+2~5
- **방법론**: AI 텍스트 분석 + O*NET GWA 참조 분류
- **출력**: 직업별 직무기술 정의서, 유사성 매트릭스

### 3.4 onet-comparator (해외사례 비교분석)
- **위치**: `.claude/skills/onet-comparator/`
- **역할**: O*NET/ESCO/NOC 등 해외 체계와 국내 체계 비교분석
- **트리거**: "O*NET", "해외사례", "국내외 비교"
- **연구 단계**: M+1~3
- **출력**: 체계별 구성요소 대응표, 한국 적용가능성 평가서

### 3.5 framework-simulator (시뮬레이션 검증)
- **위치**: `.claude/skills/framework-simulator/`
- **역할**: 프레임워크를 중분류 직업군에 시범 적용, 타당성 검증
- **트리거**: "시뮬레이션", "검증", "시범적용"
- **연구 단계**: M+5~7
- **출력**: 시뮬레이션 결과, 전문가 검토자료, 최종 조정안

## 4. 기존 스킬 활용 계획

| 기존 스킬 | 활용 용도 | 시기 |
|---|---|---|
| **docx** | 착수/중간/최종 보고서 작성 | 보고회 전 |
| **pptx** | 제안발표, 보고회 발표자료 | 보고회 전 |
| **xlsx** | 데이터 분석 시트, 비교표 | 수시 |
| **pdf** | RFP 분석, 참고문헌 처리 | 수시 |
| **data:analyze** | 수집 데이터 탐색 및 분석 | M+2~ |
| **data:create-viz** | 시뮬레이션 결과 시각화 | M+5~ |

## 5. 연구 단계별 AI 활용 맵

### M+1: 착수 단계
```
[사람] 계약 체결, 발주기관 미팅, 착수보고 준비
[AI]   ksco-data-collector: 공개 데이터 선행 수집 시작
       onet-comparator: O*NET 데이터셋 다운로드 및 구조 분석
       pm-dashboard: 상세 일정표 생성
       pptx/docx: 착수보고서·발표자료 생성
```

### M+2~3: 데이터 수집 + 사례분석
```
[사람] 발주기관 데이터 협조 요청, 전문가 자문 섭외
[AI]   ksco-data-collector: 전체 데이터 수집·정제 완료
       onet-comparator: 해외 5개 체계 + 국내 3개 체계 분석 완료
       nlp-job-analyzer: 파일럿 분석 (일부 직업 테스트)
       docx: 중간점검(1차) 자료 생성
```

### M+3~5: 핵심 분석 + 프레임워크 설계
```
[사람] 프레임워크 설계 방향 의사결정, 전문가 자문
[AI]   nlp-job-analyzer: 전체 직업 분석 실행 (배치 처리)
       직무기술 정의서 초안 생성
       프레임워크 구조 설계 초안
       docx: 중간보고서 생성
```

### M+5~7: 시뮬레이션 + 검증
```
[사람] 전문가 검토회의 주관, 피드백 수렴
[AI]   framework-simulator: 시뮬레이션 실행 및 분석
       전문가 검토자료 생성
       피드백 반영 조정
       docx: 중간점검(2차) 자료, 최종보고서(안) 생성
```

### M+7~8: 최종 정리
```
[사람] 최종보고회 발표, 발주기관 승인 절차
[AI]   docx: 최종보고서 완성
       pptx: 최종보고회 발표자료
       최종보고서 인쇄용 편집
```

## 6. AI 품질 관리 원칙

1. **전문가 검토 필수**: 모든 AI 분석 결과는 전문가(조세형 PI) 검토 후 확정
2. **샘플 검증**: 배치 처리 전 반드시 샘플 10~20개로 품질 확인
3. **이중 검증**: 시뮬레이션 결과는 정량적 분석 + 전문가 정성 평가 병행
4. **버전 관리**: 모든 AI 산출물은 날짜+버전으로 관리
5. **프로세스 투명성**: AI가 어떤 방법으로 분석했는지 보고서에 명시
