## 0. 문서의 위상

본 문서는 본 연구가 산출해야 할 두 개의 핵심 결과물 — ① **KSCO 직업별 직무기술 정의서**, ② **한국형 직업정보 프레임워크 설계서** — 의 **상위 설계도(Master Blueprint)** 다. 목차안(2026-05) Ⅳ장(프레임워크 설계)·Ⅴ장(KSCO 직무활동 표준화)·Ⅵ장(시범적용)의 골격에 그대로 대응한다.

## 0.1 본 연구 스코프 (v1.4 확정)

**범위 IN — 본 연구 (8개월, 6,500만원)**:
- 한국형 6대 차원 중 **"업무(Work Activities)" 차원에 집중** — TASK → DWA → IWA → GWA 4계층 구축
- **Responsibility 3축 점수화** (관리·감독·안전) — 본 연구 차별화 포인트
- **ISCO-28 SLF 4차원 매핑 슬롯** (Education·Resp·Exp·WBL) — Resp는 본 연구 신규 도출, 나머지 3차원은 외부 데이터 매핑 슬롯만 제공

**범위 OUT — 차기 KSCO 9차 또는 후속 연구 과제로 명시**:
- ~~한국형 6대 차원 중 나머지 5차원 (지식·기술·능력·도구·환경) 의 전수 도출·측정~~ → **[D1 대체]** 도구·환경은 **IN**(TASK와 1회 동시 추출, 부분 커버리지). OUT은 **지식·기술·능력 3차원**으로 한정
- BARS 행동 앵커 5차원 적용 (업무 차원에 한해 1차 시범)
- 직업별 incumbent survey (전문가 surrogate로 대체)

→ 본 결정의 근거: 예산·자원 제약. 6대 차원 동시 처리 시 NLP 작업량 6배·전문가 검토 부하 6배. 본 연구는 **가장 차별화·정책 활용성 높은 "업무 차원 + R3축"** 에 자원을 집중한다. 보고서 Ⅴ장 첫 절에 본 결정과 근거 명시.

핵심 메시지 여섯 줄:

1. KSCO 8차 495 세분류의 **직업설명 텍스트**를 입력으로, **TASK → DWA → IWA → GWA** 4계층 직무활동 체계와 **Responsibility(관리·감독·안전) 3유형**을 **동시에** 도출한다.
2. 도출은 **NLP 5단계 파이프라인** + **전문가 검증 게이트(HumRRO 한국화 임계치)** 의 이중 구조로 한다.
3. **방법론적 정당성은 O\*NET Work Activities Project(2014) 절차를 1:1로 따른다.** 단 8개월·2인팀 제약상 ONET의 인간 분석가 작업을 **LLM이 qualitative 판단을 흉내내고 전문가는 의심구간만 검수**하는 hybrid로 변형한다 (ONET이 quantitative 접근을 기각한 이유와 우리의 변형 정당화는 §5.5 참조).
4. AI 도구는 **CLI 배치 파이프라인 + DuckDB 단일 저장소 + Streamlit 전문가 검토 웹**의 3-tier 구성으로 개발한다. 외부 의존을 줄여 단일 노트북에서도 재현 가능하다.
5. 파일럿은 **3개 중분류**(경영·금융 / 정보통신 / 보건) **약 60개 세분류**로 1차 검증 후 **495 전수**로 확장한다.
6. 동일 KSCO 코드 안에서 책무성이 다른 직업(예: 동네 치킨집 사장 vs 프랜차이즈 대표)을 **세세분류 분기 또는 책무성 태그**로 변별 가능하게 만드는 것이 본 프레임워크의 **존재 이유**이자 핵심 평가지표다.

## 4. NLP 파이프라인 — 세부 규약 (ONET 절차 1:1 정합)

### 4.1 ① 전처리

- 한국어 형태소: **Mecab-ko** (기본) + **Khaiii** (검증용 비교)
- 문장 분할: Kss 4
- 정규화: 한자(漢字) → 한글, 공백·구두점·신구 약어 표준화
- 동의어 사전(`lexicon`): KECO 2025 + 한국직업사전 동의어 항목 1차 import 후 누적
- 산출: `processed_sentences.parquet`

### 4.2 ② TASK 추출 (v1.2 — 소스 3-Layer 우선순위 적용)

**소스 데이터 우선순위 룰** (상세: `02_소스데이터_우선순위_분석.md`):

```
Layer 0 (PRIMARY · 모든 직업 적용)
  KSCO 8차 해설서: 세분류 정의 + 주요 업무 + 세세분류 정의 + 직업 예시
  - 가중치 1.0, 출처 메타 "KSCO_HS"
  - 실측 평균 5~10 task/직업, 권위 100%(통계청 고시)
                            │
                            ▼ Trigger 통과 시만
Layer 1 (SECONDARY · 조건부)
  한국직업사전 — ISCO 평가연구 부록4 연계표 기반 N:1 매핑 합집합
  - 가중치 0.7, 출처 메타 "KJD_GROUP" + source_subject(원 직업명)
                            │
                            ▼ 그래도 부족 시 (예상 < 5%)
Layer 2 (TERTIARY · 극단 부족)
  NCS 능력단위 - 가중치 0.5, 출처 메타 "NCS"
```

**Layer 승급 트리거 (정량 임계)**:

| 트리거 | 임계 |
|---|---|
| 추출 task 수 부족 | 직업당 task < 8 |
| "주요 업무" 섹션 누락 | KSCO 해설서에 없음 (34개 추정) |
| 세분류 정의 분량 부족 | < 80자 |
| 책무성 점수 모호 | LLM 2회 R점수 자기일치 < 0.7 |
| DWA 군집 미배치 | 추출 task ≥ 30%가 군집화 실패 |

**한국직업사전 N:1 매핑 처리 (이질성을 변별력 분석에 역활용)**:

- 한국직업사전 직업명 1건 = 1개 record. KSCO 코드 + 원 직업명을 모든 task에 메타 보존
- DWA 군집 후 군집 내 `source_subject` 분포 분석 → 특정 직업사전 직업만 출현하는 DWA = "특수 DWA"로 식별
- 같은 KSCO 안에서 직업사전 직업명별 R점수 분포 → **세세분류 분기 후보 자동 추출** (치킨집 사례와 같은 변별력 분석의 직접 데이터)

**추출 절차**:

1. 규칙 기반 1차 — 동사+목적어 패턴 (`*한다 / *수행한다 / *관리한다`)
2. **LLM 추출 (Claude Opus 4 + GPT-5, §5.2)**, 동일 프롬프트 2회 독립 실행
   - 입력: 직업설명 문장 단위 (Layer별로 분리)
   - 출력 JSON: `[{verb, object, full_statement, confidence, source, source_subject}]`
   - 교차일치율 ≥ 0.85 미달 시 플래그
3. 형식 정규화: `동사 + 목적어 + (수단/맥락 옵션)` — O\*NET task statement 규약 차용
4. HumRRO 게이트(현장 적용 시): 최소 응답자 N=10, relevance ≥ 50%, mean importance ≥ 3.0
5. **중복 통합**: 동일·유사 task 발견 시 L0(KSCO) 우선 보존

산출: `tasks.parquet`, **L0 직업당 평균 5~10 / L0+L1 직업당 평균 15~25** (HumRRO -0.64 보정 적용)

### 4.3 ③ DWA 도출 — ONET 3-pass 절차 1:1 차용 (v1.1 핵심 보강)

ONET WA 보고서 Section III의 **"Task Clustering 3-step + DWA Writing + QC"** 절차를 한국·LLM 맥락으로 변환.

#### Step 3a — Job Family 분할 (ONET Step 1)

> ONET은 22개 SOC Major Groups를 Job Family로 채택. 우리는 KSCO 중분류 57 vs KECO 24 중 택해야 함 (§8 결정사항 ①).

- ~~권장: **KECO 24 직무군**~~ → **[D2 확정] KECO 중분류 40 (실측, `mapping_ksco_keco`)**. 텍스트 분석에 더 친화적 입자도. KSCO 중분류 57은 통계 표준이지만 입자도 편차 큼. (※ "24"는 미실측 추정치였음)
- 산출: 각 task에 `job_family_id` 부여, 1차 분할 완료.

#### Step 3b — GWA 버킷 할당 (ONET Step 2)

> ONET은 3–4인 분석가가 41 GWA 중 하나에 각 task 1:1 할당 → consensus. 우리는 LLM 2-회 독립 실행 + 자기일치성으로 대체.

- LLM 프롬프트: "이 task의 **주된** 작업 활동을 41 GWA 중 하나로 분류하라. 부수 활동·도구·목적·예시구는 무시하고 핵심 동사 의미만 본다."
- 2-회 독립 실행 → 일치 시 자동 채택 / 불일치 시 검토 큐
- ONET이 강조한 "task에 여러 활동이 있어도 1차 할당에서는 **primary activity 하나만**" 원칙 유지 (Multiple Linkage는 §4.4에서 별도 처리)
- 산출: `task.primary_gwa_id` 채움

#### Step 3c — GWA 내 군집 + DWA 라이팅 (ONET Step 3)

> ONET은 GWA 버킷 안에서 7단계 정밀 클러스터링. 우리는 임베딩+HDBSCAN+LLM 라이팅으로 압축.

- 임베딩: **bge-m3** (다국어, ONET 영문 동시 비교 가능)
- 군집: HDBSCAN, min_cluster_size=4, min_samples=2 — **GWA 버킷 단위로** 실행 (전체 task에 한 번에 적용하지 않음)
- 라벨링(=DWA 작성): 군집 중심 5개 task를 LLM에 넣어 **DWA Writing Standards 8조항 (한국어판)** 강제

##### DWA Writing Standards 한국어판 8조항 (v1.1 신설)

ONET 본문 25페이지 발췌를 한국어 직업 문맥에 맞게 변환:

1. **하나의 주된 행동 동사만 사용**. DWA는 그 동사로 시작.
2. **현재형·서술형** 어미 통일 (예: "한다", "수행한다", "관리한다").
3. **명사는 최소한**으로 쓰되 구체적. 여러 객체는 "또는"으로 연결.
4. **명사 일반화 수준은 Job Family 단위에 맞춤**: 너무 일반("기계") · 너무 특수("CT-7 절삭로봇") 모두 금지. 중간("의료 영상 장비") 권장.
5. 필요 시 형용사로 직업 맥락 명시.
6. **"예: …", "포함하여 …" 같은 예시구는 회피** (불가피한 경우 1개).
7. **목적절("…를 위해", "…하기 위해")는 활동 의미 식별에 필수일 때만**. 가능한 경우 동사구로 흡수.
8. **중학교 2학년 가독성** 수준. 전문 용어는 직업·산업 표준 용어 한정.

→ 이 8조항을 LLM 라벨링 프롬프트에 명시적으로 박는다. 산출된 DWA가 8조항 위반 시 LLM 재작성.

#### Step 3d — DWA 임계치·QC

- **채택 임계치**: 최소 **4 task** 또는 **3 직업**에서 언급 (ONET 동일)
- **DWA QC 4기준 (ONET 본문 명시)**:
  1. **군집 동질성 (Cluster homogeneity)** — 군집 내 task들이 같은 활동을 가리키는가
  2. **task–군집 적합성 (Task-cluster fit)** — 개별 task가 그 군집에 정확히 속하는가
  3. **DWA 특수성 (Specificity)** — 너무 일반적이지 않은가
  4. **DWA 유일성 (Uniqueness)** — 다른 DWA와 개념적 중복은 없는가
- **Round-Robin QC 2회**: 1차 LLM self-check → 2차 LLM 교차 검증 (다른 모델) → 위원 검토 (위반 항목만)
- 산출: `dwa_candidates.parquet`, 목표 1,500–2,000

### 4.4 ④ DWA 정련 → IWA 도출 — ONET Section IV·V 순서 (v1.1 순서 수정)

> **v1.0 오류 정정**: 기존 v1.0은 "한국 DWA → ONET 332 IWA로 매핑"이라고 적었으나, ONET 원본은 그렇게 하지 않았다. ONET은 (a) DWA 정련 후 (b) **DWA를 다시 군집화하여 한국 IWA를 새로 작성**한 다음 (c) ONET IWA·GWA와 비교한다. 순서를 바로잡는다.

#### Step 4a — Cross-Job-Family DWA 통합

- 알파벳·코사인 정렬로 동일·근접 DWA 식별
- 근접 DWA의 task 풀을 합쳐 클러스터 동질성 재검토
- 통과 시 표준 DWA로 통합, `is_cross_family=True` 플래그
- **활용**: 산업 간 직업 전환 가능성 분석의 기초 데이터 (산출물 ⓕ)

#### Step 4b — Multiple Linkage 부여

- 하나의 task가 둘 이상의 활동을 포함하는 경우 — task당 **최대 3개 DWA**에 연결
- 제약: **같은 Job Family 내 DWA에만** 연결 (ONET 규약)
- 2-pass 분석 (1차 분석가 → 2차 분석가 검증)을 LLM 2-회 self-consistency로 대체
- 저장: `task_to_dwa.link_order ∈ {1,2,3}`

#### Step 4c — 한국 DWA 재클러스터링 → 한국 IWA 도출

- DWA 정련 완료본을 다시 임베딩 → HDBSCAN (min_cluster_size=4)
- 군집당 LLM 라벨링 (8조항 + IWA는 DWA보다 한 단계 추상)
- 목표: **한국 IWA 250–330개**

#### Step 4d — ONET IWA(332) · GWA(41) 비교 매핑

- 한국 IWA ↔ ONET IWA 코사인 매칭 (Top-3 후보)
- Top-1 코사인 < 0.55 → **한국 신규 IWA**로 격리 + 별도 라벨
- IWA → GWA 매핑은 ONET 41 GWA 상한 + 한국 신규 1–4 한도
- 모든 매핑 LLM 더블 체크
- 산출: `dwa_iwa_gwa_map.parquet`, ISCO-28 SLF 영역 라벨 동시 부여

### 4.5 ⑤ Responsibility 3축 점수화

본 연구의 **차별화 포인트**. ISCO-28 SLF는 책무성을 독립 차원으로 격상하나 측정 방법론은 모호하다. 본 연구는 다음 3축으로 정량화한다.

| 축 | 정의 (ISCO-28) | 측정 가능 단서 (KSCO·직업사전 텍스트) |
|---|---|---|
| **관리책무성 (Mgmt)** | 사람·예산·전략에 대한 결정권 | "직원 채용/해고", "예산 편성", "전략 수립", "사업 방향 결정", 부서·법인 규모 키워드 |
| **감독책무성 (Supervisory)** | 타인의 업무를 지시·검토 | "감독한다", "지도한다", "검토 승인", "팀을 이끈다" |
| **안전책무성 (Safety)** | 자신·타인·환경의 안전 책임 | "안전 점검", "사고 예방", "위험물 관리", 인명 보호 관련 단서, 환경 보호 단서 |

각 축은 0–3점 (없음 / 약함 / 보통 / 강함). 점수 부여는:

1. **단서 룰북**으로 1차 후보 키워드 매칭 + 빈도
2. **LLM 점수 부여**: 직업설명 전체 + 추출 task 리스트를 입력 → 0–3 점수 + 근거 스팬 출력
3. **2-회 self-consistency**: 동일 입력 2회 → 점수차 ≤1 일치율 측정
4. **전문가 보정 게이트**: 일치율 미달 또는 점수≥2 직업은 전문가 검토 강제

**치킨집 사례 적용**:

| 직업 (가상) | Mgmt | Sup | Safety | 합계 |
|---|---|---|---|---|
| 가맹점주(3인 운영) | 1 | 1 | 1 | 3 |
| 프랜차이즈 본사 대표 | 3 | 3 | 2 | 8 |

→ 동일 KSCO 코드라도 **책무성 점수 격차 ≥ 4** 시 **세세분류 분기 후보**로 자동 플래그. 이게 본 연구 시뮬레이션 단계(Ⅵ)에서 "분류체계 변별력 검증"의 핵심 지표가 된다.

### 5.5 ONET이 quantitative를 기각한 이유와 우리의 변형 정당화 (v1.1 신설)

ONET WA 보고서 Section II는 명시한다 — DWA 개발 시 **quantitative 접근(언어 분해 + 분류 + 클러스터 분석)을 검토했으나 기각**하고 qualitative human judgment를 채택했다. 기각 사유: "task statement 구조가 너무 다양해 기술 시스템이 핵심 활동 정보를 안정적으로 추출하기 어렵다(2014)".

본 연구의 변형 근거:

| ONET 2014 (인간) | 본 연구 2026 (LLM hybrid) | 비고 |
|---|---|---|
| 3–4인 분석가가 GWA 할당 → consensus | LLM 2-회 독립 실행 → self-consistency | 인간 4명 토론을 시뮬레이션 |
| 분석가가 task→DWA 라벨 작성 (8조항) | LLM이 8조항을 프롬프트로 강제 받아 작성 | 8조항 위반은 LLM 재작성 |
| Round-Robin QC 2회 (두 팀이 교차 검토) | **Claude Opus 4 + GPT-5 (최상위급 2종) 교차 검증** | 모델 다양성이 팀 다양성 대체 |
| 모든 단계 인간 합의 | **위반·저신뢰 항목만 전문가 검토** | 전문가 작업량 1/10 이하로 축소 |

**핵심 메시지**: LLM의 의미 이해 수준은 2014년 NLP 대비 질적 도약을 했으므로 ONET이 거부했던 "기술적 자동화"의 전제가 바뀌었다. 단, **자동화 출력에 대한 인간 게이트는 유지**한다. 이게 학회·통계청 Q&A 방어 핵심 논리.

### 6.4 (v1.3 신설) CBM 분류 모델 학습 — 시뮬레이션 단계 옵션

1. **ISCO-28 SLF 직능수준 SL1~4 자동 판정**

## 7. ISCO-28 SLF 정합성 — 4차원 슬롯 매핑

| ISCO-28 SLF 차원 | 본 프레임워크 슬롯 | 출처 |
|---|---|---|
| **Education** | KSCO·KECO 학력 정보 + 임금직업포털 + 자격훈련 | 외부 데이터 import |
| **Responsibility** | **본 프레임워크 ⑤ Responsibility 3축 점수** | NLP 자체 도출 (차별화) |
| **Experience** | 한국직업사전 숙련기간 + 채용공고 | 외부 데이터 import |
| **WBL** | 일학습병행제 매핑 | 외부 데이터 import |

→ Education·Experience·WBL은 기존 인프라 import, **Responsibility는 본 연구가 새로 만드는 것**. 이게 본 연구가 ISCO-28 도입에 기여하는 가장 큰 부분이며, 동시에 KSCO 개편(특히 같은 코드 내 책무성 변별)의 정량적 근거가 된다.
