한국 직업의 "하는 일"을 4단계로 자동 정리하는 법
TASK → DWA → IWA → GWA 도출 설계

한국표준직업분류(KSCO) 직업설명 글을 컴퓨터(AI)에게 읽혀, 직업들이 실제로 하는 일을 네 단계의 "작업활동 사전"으로 만들어내는 방법을 — AI 전문가가 아니어도 이해할 수 있게 — 정리했습니다.

📥 입력 : KSCO 8차 직업설명 1,270개 📤 출력 : 4계층 작업활동 사전 + 연결망 🧠 핵심 도구 : Claude Opus 4.8 · 의미 임베딩 · 군집 📅 2026-06-09 · v1.0
① 왜·무엇을 ② 4계층이란 ③ 전체 흐름 ④ 단계별 방법 ⑤ 이론·공식 쉽게 ⑥ 코드가 하는 일 ⑦ 믿을 수 있는 이유·한계

1우리가 풀려는 문제

"이 직업은 무슨 일을 하는가"를 사람마다 다르게 적으면 직업끼리 비교할 수 없습니다. 그래서 공통의 언어(작업활동 사전)가 필요합니다.

지금의 문제

KSCO 직업설명은 직업마다 문체·상세도가 제각각입니다. "회계사는 재무제표를 작성한다", "세무사는 세금 신고서를 만든다" — 글로는 달라 보이지만 본질은 같은 활동일 수 있습니다.

목표

모든 직업의 활동을 같은 기준의 단계별 사전으로 정리해서 ①같은 코드 안에서도 다른 직업을 구분하고 ②국제표준(O*NET)과 비교하고 ③직업 간 전환 가능성을 분석할 수 있게 만듭니다.

🍳 비유로 이해하기. 요리법 수천 개가 있다고 합시다. "양파를 썬다", "마늘을 다진다"는 서로 다른 문장이지만 묶으면 '채소 손질'이라는 더 큰 활동이 됩니다. 이걸 또 묶으면 '조리 준비', 가장 크게 묶으면 '음식 만들기'가 됩니다. 우리가 하는 일이 바로 이것 — 수많은 "하는 일"을 작은 단위 → 중간 단위 → 큰 단위로 차곡차곡 묶어 올리는 것입니다.

2네 개의 계층 — 작은 일에서 큰 활동으로

맨 아래 구체적인 "한 가지 일(TASK)"에서 출발해, 비슷한 것끼리 묶어 위로 올라갈수록 더 일반적인 활동이 됩니다. 미국 노동부 O*NET이 쓰는 4계층 구조를 그대로 따릅니다.

GWA일반화 작업활동 · 41개
가장 큰 활동 범주. 직업·산업과 무관한 보편 활동.
예: "정보 입수", "데이터·정보 분석" (명사형)
IWA중간 작업활동 · 약 300개
여러 DWA를 포괄하는 중간 단계.
예: "재무·투자 정보를 분석하여 평가한다"
DWA상세 작업활동 · 약 2,000개
여러 직업이 공유하는 구체적 활동.
예: "재무 기록을 조사하여 재무제표를 작성한다" (회계사·세무사·신용분석가 공통)
TASK과업 · 직업당 8~30개
한 직업이 하는 가장 구체적인 한 가지 일. "동사+목적어" 한 문장.
예: "도면을 검토하여 형태를 확인한다"
핵심 한 줄. TASK(작은 일)를 비슷한 것끼리 묶으면 DWA, DWA를 또 묶으면 IWA, 마지막으로 가장 크게 묶으면 GWA. 아래에서 위로 쌓아 올리는 "상향식(bottom-up)" 방식입니다.

중요한 특징 : 깔끔한 나무가 아니라 "얽힌 그물"

하나의 TASK가 꼭 하나의 DWA에만 속하는 건 아닙니다. 한 가지 일이 두세 개의 활동에 걸칠 수 있습니다(최대 3개). 그래서 전체 구조는 단순한 가계도가 아니라 부분적으로 얽힌 그물망이 됩니다. (O*NET 실측: 평균 1.26개, 최대 3개에 연결)

3전체 흐름 한눈에 (5단계)

KSCO 원문에서 시작해 4계층 사전이 완성될 때까지의 자동 처리 과정입니다. 각 단계의 결과는 하나의 데이터베이스 파일(DuckDB)에 차곡차곡 저장됩니다.

사람·LLM 없이 규칙(정규식)만으로 처리. "깨끗한 입력"까지만 책임집니다.

4단계별 방법 — 무엇을·어떻게·왜

각 단계가 실제로 무엇을 하는지, 왜 그렇게 하는지를 풀어 설명합니다.

Stage 1  TASK 추출 — AI가 직업설명을 읽는다

방법. 최신 AI 모델(Claude Opus 4.8)에게 "당신은 직무분석 전문가다. 이 직업설명에서 하는 일을 동사+목적어 형태로 뽑아라"라고 지시하고, 정해진 형식(JSON)으로만 답하게 합니다.

  1. 2번 패스로 특화 — (1차) 상위 직업의 주요 업무로 활동 골격을 잡고 → (2차) 이 직업만의 정의·예시로 구체화.
  2. 같은 글을 2번 독립 추출 — AI도 매번 약간 다르게 답할 수 있으므로, 2번 읽혀 둘을 합칩니다(하나라도 나온 건 포함 = 누락 최소화). 두 번 다 나온 건 신뢰도를 높게 줍니다.
  3. 개수 기준 — 직업당 8~30개(상한 40). O*NET 실측(직업당 중앙값 20개)을 근거로 삼습니다.
  4. 추적 정보 기록 — 각 TASK에 "어느 문장에서 나왔는지"를 같이 적어, 엑셀만 봐도 출처를 알 수 있게 합니다.
정직한 한계. 도구·작업환경은 직업설명에 명시적으로 적혀 있을 때만 추출합니다(추측 금지). 사무직처럼 도구 언급이 적으면 비워 둡니다 — KSCO 원문의 한계를 그대로 인정.

Stage 2  DWA 도출 — 비슷한 일끼리 묶는다

방법. 컴퓨터는 글의 "의미"를 직접 모릅니다. 그래서 먼저 각 문장을 숫자 목록(벡터)으로 바꾼 뒤(=임베딩), 숫자가 가까운 것끼리 묶습니다(=군집).

① 임베딩
문장 → 1,024개의 숫자. 의미가 비슷하면 비슷한 숫자가 됩니다. (모델: bge-m3, 다국어라 한국어·영어 비교 가능)
② 계층 군집
가장 가까운 둘부터 차례로 묶어 "묶음 나무(가계도)"를 만듭니다. 나무를 특정 높이에서 자르면 묶음(DWA)이 결정됩니다.

이름 붙이기. 각 묶음의 대표 문장 5개를 AI에게 주고 8가지 작성 규칙(O*NET 표준)에 맞춰 정식 이름을 짓게 합니다. 규칙 위반 시 다시 쓰게 합니다(최대 3회).

채택 기준. 너무 작은 묶음(4개 미만 TASK 또는 3개 미만 직업)은 잡음으로 보고 DWA로 인정하지 않습니다. (O*NET과 동일 기준)

Stage 3  IWA 도출 — 한 단계 더 일반화

Stage 2에서 만든 같은 묶음 나무를 더 높은 곳에서 자릅니다. 그러면 DWA들이 더 큰 묶음(IWA)으로 합쳐집니다. 같은 나무를 쓰기 때문에 "같은 DWA는 반드시 같은 IWA에 속한다"가 저절로 보장됩니다. 이름은 DWA보다 한 단계 일반적인 동사구로 AI가 작성.

Stage 4  GWA 도출 — 국제표준에 연결

가장 큰 범주(GWA)는 데이터만으로 뽑기 어렵습니다(전문가가 설계한 분류라서). 그래서 두 갈래로 진행합니다.

갈래방법목적
(주) 하이브리드O*NET의 41개 GWA를 한국어로 번역해 상위 범주로 채택하고, 우리 IWA를 가장 가까운 GWA에 연결국제 정합성 확보(정석)
(탐색) 순수 상향식한국 데이터만으로 최상위까지 묶어보고 → O*NET과 몇 % 일치하는지 측정한국 직업의 고유성 검증(학술)

연결이 약한(유사도 0.55 미만) 활동은 "한국 고유 GWA"로 따로 표시합니다.

5이론과 공식 — 쉽게 풀이

파이프라인을 떠받치는 4가지 핵심 아이디어. 수식은 "이게 무슨 뜻이냐면"으로 함께 설명합니다.

① 왜 의미를 숫자로 바꿀 수 있나 — 분포가설

언어학의 오래된 원리: "비슷한 맥락에서 쓰이는 말은 비슷한 의미를 가진다"(Harris 1954). "재무제표를 작성한다"와 "회계장부를 만든다"는 비슷한 단어·맥락이라, 숫자로 바꿔도 가까운 위치에 놓입니다. 이게 군집의 근거입니다.

② 두 문장이 얼마나 비슷한가 — 코사인 유사도

문장을 숫자(화살표)로 바꾼 뒤, 두 화살표가 같은 방향을 가리키는 정도를 잽니다. 같은 방향이면 1(같은 의미), 직각이면 0(무관).

cos(A, B) = A · B  (길이를 1로 맞춘 경우)
→ 값이 1에 가까울수록 의미가 비슷. DWA 묶음은 평균 0.70 이상이어야 "잘 뭉쳤다"고 봅니다.

③ AI를 2번 돌린 결과가 얼마나 겹치나 — 자카드(Jaccard)

같은 직업설명을 AI가 2번 읽으면 결과가 조금 다를 수 있습니다. 두 결과가 얼마나 겹치는지를 잽니다.

겹침 = (양쪽에 다 나온 개수) ÷ (전체 개수)
→ 1이면 완전히 같음. 우리는 이 값을 "기록"만 하고, 실제 채택은 둘을 합쳐서(합집합) 합니다 — 누락을 최소화하기 위해. (두 번 다 나온 TASK는 신뢰도 0.95, 한 번만 나온 건 0.80)

④ 비슷한 것끼리 자동으로 묶기 — 계층적 응집 군집

가장 가까운 둘부터 차례차례 묶어 하나의 큰 나무로 만드는 방법입니다. 이 나무를 낮게 자르면 작은 묶음(DWA), 높게 자르면 큰 묶음(IWA·GWA)이 됩니다.

왜 이 방법인가? ①결과가 항상 같음(재현성 — 통계청 요건) ②모든 TASK가 반드시 어딘가에 속함(빠짐 없음) ③계층이 자동으로 일관됨.
※ 다른 후보였던 'HDBSCAN'은 38~62%가 어디에도 못 묶이는 문제로 부적합 판정되어 채택하지 않았습니다.

6코드가 실제로 하는 일

실제 가동 중인 현행 코드(TEST1/ 폴더)의 핵심 부분입니다. 코드 옆의 회색 글이 "이게 하는 일"입니다.

가. TASK 2회 결과 합치기 (Stage 1 · s1_extract.py)

# AI를 2번 독립 실행한 결과(outs)를 받아 하나로 합친다
CONF_BOTH = 0.95   # 2번 다 나온 TASK → 신뢰도 0.95
CONF_ONE  = 0.80   # 1번만 나온 TASK → 신뢰도 0.80

def union_runs(outs, code):
    # 1) 두 결과가 얼마나 겹치는지 계산해서 "기록만" 한다 (채택 기준 아님)
    cross = jaccard(sets[0], sets[1])
    # 2) (동사,목적어)가 같으면 같은 TASK로 보고 합친다 = 합집합
    for o in outs:
        for t in o["tasks"]:
            counts[k] += 1            # 몇 번 나왔는지 센다
    # 3) 2번 이상 나왔으면 0.95, 아니면 0.80 신뢰도 부여
    tasks = [{**t, "confidence": CONF_BOTH if counts[k]>=2 else CONF_ONE}]
    return {"tasks": tasks, "cross_consistency": cross}

다. 묶음이 잘 뭉쳤는지 점수 매기기 (Stage 2 응집도)

def mean_cosine(emb):
    # 묶음 안 모든 문장 쌍의 평균 유사도 = 응집도
    sims = emb @ emb.T
    return (sims.sum() - n) / (n*(n-1))   # 자기자신 제외 평균
    # 이 값이 0.70 이상이어야 "잘 뭉친 DWA"로 인정

→ 한 줄 요약: "한 묶음 안 문장들이 서로 얼마나 비슷한지 평균을 내, 0.70 미만이면 엉성한 묶음으로 보고 거른다."

저장 방식. 모든 단계 결과는 pipeline.duckdb 파일 하나에 들어갑니다. 이 파일만 복사하면 전체 작업이 그대로 재현됩니다 — "같은 입력 → 같은 결과"라는 통계청 요건을 만족합니다.

7믿을 수 있는 이유 — 그리고 정직한 한계

✓ 재현성
모든 과정이 코드로 고정 → 누가 언제 돌려도 같은 결과. 파일 하나로 검증 가능.
✓ 설명가능성
GWA → IWA → DWA → TASK → 원문장까지 거꾸로 추적 가능. "왜 이 분류인가"에 답할 수 있음.
✓ 국제 정합성
O*NET의 검증된 절차를 그대로 차용 + O*NET과 직접 비교로 타당성 확인.
