# CBM (설명가능 AI) — 본 연구와의 정합성 분석

> 작성: 이석주 · 2026-05-29

## 0. 핵심 결론 (3줄)

1. **본 연구의 NLP 파이프라인 4계층(Task → DWA → IWA → GWA) + Responsibility 3축은 사실상 자연어판 Concept Bottleneck Model 구조다.** 별도 모델 도입 없이 **명명·정합성 명시만으로 즉시 적용 가능**.
2. **Streamlit 검토 웹은 CBM의 "Intervention layer" 그 자체** — 전문가가 잘못된 concept을 직접 수정하면 최종 분류 판정이 즉시 갱신되는 구조. CBM 원논문이 강조하는 핵심 가치(human-AI 협업)를 우리는 이미 설계에 포함.
3. **시뮬레이션 단계(M+5~7)에 명시적 CBM 분류 모델을 추가 학습**하면 "직능수준 SL1–4 자동 판정" 과 "분류체계 개편 후보 자동 추천" 도구로 확장 가능. **이게 본 연구의 정책 활용성을 결정적으로 강화**한다.

## 1. CBM 핵심 개념 정리 (발표자료 + 원논문)

### 1.1 일반 AI vs CBM

| 항목 | 일반 AI (black-box) | **CBM (white-box)** |
|---|---|---|
| 구조 | 입력 → 신경망 → 출력 | 입력 → **Concept layer (인간 이해 가능)** → 출력 |
| 설명 | 사후 해석(SHAP·LIME 등 별도 분석) | **구조 자체가 설명** |
| 수정 | 출력 틀려도 교정 불가 | **Intervention** — 사람이 concept을 직접 수정 → 출력 즉시 갱신 |
| 신뢰 | "왜 그렇게 판단했나"가 불명확 | concept 값으로 역추적 가능 |

### 1.2 CBM 단점과 최신 연구 (발표자료 p.21~28)

| 단점 | 최신 연구 | 본 연구의 대응 |
|---|---|---|
| concept 라벨링 비용·시간 | **Label-free CBM (Oikarinen 2023)** — LLM·VLM 자동 라벨링 | 본 연구는 **Claude Opus 4 + GPT-5로 자동 concept 도출** — Label-free 구조 차용 |
| concept 후보군 선택에 따라 성능 차이 큼 | concept 자동 발견 연구 | 본 연구는 **ONET GWA 41 + IWA 332 + DWA 2,069** 라는 검증된 concept 백본 사용 |
| 기존 모델보다 예측 성능 저하 | 자연어 확장 연구 | 본 연구는 **분류 정확도가 최종 목표가 아님** — 설명가능성·활용성이 핵심 |

### 1.3 적용 분야

발표자료는 의료(폐렴·폐암 진단), 신용평가, 생성형 AI(환각 방지)를 예시로 들었다. **공통점**: "법적·사회적 책임이 큰 의사결정 영역" → 본 연구의 **표준직업분류 개편 (통계청 고시 행정규칙)** 도 정확히 동일 카테고리.

## 2. 본 연구 4계층 ↔ CBM Concept Hierarchy 1:1 매핑

```
┌────────────────────────────────────────────────────────────────────┐
│  INPUT  KSCO 직업설명 텍스트 (1,036p 해설서 + 직업사전 보강)        │
└────────────────────────────────┬───────────────────────────────────┘
                                 ▼
┌────────────────────────────────────────────────────────────────────┐
│  CONCEPT LAYER 1  Tasks (직업당 5~25개, 가장 미시 concept)          │
└────────────────────────────────┬───────────────────────────────────┘
                                 ▼
┌────────────────────────────────────────────────────────────────────┐
│  CONCEPT LAYER 2  DWAs (1,500~2,000, 직업 간 공유 concept)          │
└────────────────────────────────┬───────────────────────────────────┘
                                 ▼
┌────────────────────────────────────────────────────────────────────┐
│  CONCEPT LAYER 3  IWAs (250~330, Job Family 간 공유 concept)        │
└────────────────────────────────┬───────────────────────────────────┘
                                 ▼
┌────────────────────────────────────────────────────────────────────┐
│  CONCEPT LAYER 4  GWAs (35~45, 가장 일반화된 concept)               │
│                                                                    │
│  CONCEPT LAYER 4+  Responsibility 3축 (Mgmt·Sup·Safety, 0–3점)     │
│  CONCEPT LAYER 4+  ISCO-28 SLF 4차원 슬롯 (Edu·Resp·Exp·WBL)        │
└────────────────────────────────┬───────────────────────────────────┘
                                 ▼
┌────────────────────────────────────────────────────────────────────┐
│  OUTPUT  ┌─ ISCO-28 SLF 직능수준 (SL1~4) 판정                       │
│         ├─ KSCO 분류체계 개편 후보 (세세분류 분기·통합·신설)         │
│         └─ 직업 전환 가능성 (Cross-Family DWA 공유도)              │
└────────────────────────────────────────────────────────────────────┘
        ▲                                                            
        │  ◀── INTERVENTION: 전문가 검토 웹 (Streamlit)              
        │      위반·저신뢰 concept을 직접 수정 → 출력 즉시 갱신         
└────────────────────────────────────────────────────────────────────┘
```

→ **본 연구의 4계층 자체가 다중 레벨 concept bottleneck**. ONET이 manual로 만든 GWA·IWA·DWA를 우리는 LLM 기반 Label-free CBM 방식으로 한국에 재구성하는 것.

### 2.1 직업별 그래프 — 사용자 질문 "결국 다 연계되는 거지?" 에 대한 답

**그렇다. 모든 직업이 자기만의 4계층 그래프로 연결된다.** DuckDB 스키마(`task_to_dwa`, `dwa_to_iwa`, `iwa_to_gwa`)가 이를 보장.

예시 — KSCO 13401 "공연·시각 예술 관련 관리자" 의 직무기술 정의서 (예상 출력):

```
13401  공연·시각 예술 관련 관리자
  │
  ├─ Tasks (8개)
  │   ├─ T-13401-001 "공연 기관의 경영방침을 수립한다"
  │   │     └─ DWA-K-0421 "기관 경영 전략을 수립한다"
  │   │           └─ IWA-K-087 "조직 운영 방향을 결정한다"
  │   │                 └─ GWA-K-26 "조직 전략 수립"
  │   ├─ T-13401-002 "전문가·기술직·사무직 채용·배치를 관리한다"
  │   │     ├─ DWA-K-0143 "인력 채용·배치를 관리한다"  [Cross-Family]
  │   │     │     └─ IWA-K-014 "인적자원을 관리한다" → GWA-K-31 "사람 지휘·동기부여"
  │   │     └─ DWA-K-0398 "전문 직무 교육·훈련을 기획한다"
  │   │           └─ IWA-K-201 "직무 역량 개발을 지원한다" → GWA-K-32 "타인 개발·지도"
  │   ├─ T-13401-003 …
  │   └─ … (총 8개)
  │
  ├─ Responsibility 3축
  │   ├─ Mgmt   : 3 (경영방침 수립·인사 결정권)
  │   ├─ Sup    : 3 (전문가·기술직·사무직 감독)
  │   └─ Safety : 0 (특별 단서 없음)
  │
  └─ SLF 4차원 슬롯
      ├─ Education     : ISCED 6 (학사) — KSCO 학력 import
      ├─ Responsibility: ↑ 위 3축 (합 6 → SL4 강한 시그널)
      ├─ Experience    : 5년+ (직업사전 숙련기간)
      └─ WBL           : 부분 적용 (일학습병행제 매핑 없음)
      → 종합 판정: SL4 (관리자)
```

이게 **직업 1건 = 1개 직무기술 정의서**의 최종 형태다. 모든 화살표가 명시적으로 저장되어 직업 간·산업 간 비교가 자유롭다.

### 2.2 같은 KSCO 안에서의 분기 — 책무성 변별 시나리오

CBM 구조 덕에 사용자가 든 "치킨집 사례"도 그래프 위에서 자연스럽게 해결된다:

```
KSCO 5311 (가상)  레스토랑·카페 관리자
  ├─ source_subject="동네 치킨집 가맹점주"
  │   ├─ Tasks (5개) — 주방·접객·매출 관리 중심
  │   └─ R = (Mgmt:1, Sup:1, Safety:1)  → 합 3 → SL2~3
  │
  └─ source_subject="프랜차이즈 본사 대표"
      ├─ Tasks (12개) — 전략·신규 점포·인사·재무 결정
      └─ R = (Mgmt:3, Sup:3, Safety:2)  → 합 8 → SL4

  → 변별력 분석: 같은 KSCO 5311 안에 R점수 격차 5  ≥4 임계
  → 자동 플래그: 세세분류 분기 후보 (예: 53111 단독·소규모 운영자 / 53112 다점포·본사 운영자)
```

→ 이게 **본 연구의 정책적 활용성**이며, CBM 의 white-box 구조 덕에 "왜 분기를 권고하는가" 가 R점수와 DWA 분포로 즉시 설명된다.

## 3. 적용 단계 분류 — 즉시 / 시뮬레이션 / 미적용

### 3.1 즉시 적용 가능 (현 v1.2 ~ 본 연구 종료)

| 항목 | 적용 내용 | 보고서·발표 효과 |
|---|---|---|
| **개념 정합성 명명** | 본 연구 4계층 + R 3축 + SLF 슬롯을 "다층 concept bottleneck" 으로 명시 | "단순 클러스터링 아닌 설명가능 AI 구조" 라는 정체성 부여 |
| **Intervention 메커니즘** | Streamlit 검토 웹의 Task/DWA/IWA/GWA/R 탭을 "concept intervention layer" 로 재명명 | CBM 원논문 인용 — human-AI 협업 모델의 모범 |
| **Label-free 방법론 차용** | LLM(Opus 4·GPT-5)으로 task→DWA→IWA→GWA 자동 라벨링 | Oikarinen 2023 인용 — 한국 적용의 학술적 근거 |
| **통계기준연구회 frame 활용** | 통계청 청중에게 익숙한 박석훈 발표 frame을 본 연구 정당화에 활용 | 통계청 의사결정자에게 직접 어필 |

### 3.2 시뮬레이션 단계 적용 (M+5~7, 본 연구 후반)

| 항목 | 적용 내용 | 정책 활용성 |
|---|---|---|
| **명시적 CBM 분류 모델 학습** | 직업설명 → concept layer (Tasks/DWA/IWA/GWA/R/SLF) → SLF 직능수준 판정 모델 | 통계청 분류 담당관이 신규 직업 등록 시 자동 SL1–4 추천 |
| **분류 개편 후보 자동 추천** | concept 분포 + R점수 분산으로 KSCO 분기·통합·신설 후보 자동 도출 | 차기 KSCO 9차 개정의 정량적 기초 |
| **Intervention 효과 측정** | 전문가가 concept을 수정했을 때 최종 판정이 얼마나 달라지는지 정량화 | "전문가 1명의 1시간이 모델 N% 정확도 향상" 같은 ROI 측정 |
| **Concept Activation 추적** | 어떤 task·DWA가 SL4 판정에 결정적이었는지 역추적 | 분류 결과에 대한 즉시 답변 가능 ("왜 SL3?" → "관리책무성 지수 3 + 감독책무성 2 + …") |

### 3.3 본 연구에서 미적용 (향후 연구 과제)

| 항목 | 사유 |
|---|---|
| 이미지 기반 CBM | 발표자료 원본은 의료 이미지·신용평가 위주. 본 연구는 텍스트만 |
| Concept 자동 발견 (사람 정의 없이) | 본 연구는 ONET GWA·IWA·DWA를 검증된 concept으로 사용. 자동 발견은 차기 KSCO 9차 연구의 옵션 |
| 100% 자동화 (인간 검토 제거) | ISCO-28·KSCO 모두 통계청 고시 — 법적 책임상 인간 검토 게이트는 필수 유지 |

## 4. 보고서 본문 수록 권고

### 4.1 보고서 Ⅳ장 (프레임워크 설계) 새 절 신설 권고

> **§4.X "본 프레임워크의 설명가능 AI(XAI) 구조 — Concept Bottleneck Model 정합성"**
>
> 본 연구의 직무활동 4계층(Task → DWA → IWA → GWA)과 책무성 3축, ISCO-28 SLF 4차원 슬롯은 Koh et al. (2020)의 Concept Bottleneck Model 구조와 본질적으로 동일하다. 입력(KSCO 직업설명) → 다층 concept(직무활동 4계층 + 책무성 + SLF) → 출력(직능수준 판정·분류체계 개편 권고)의 white-box 파이프라인이며, 전문가 검토 단계(Streamlit 검토 웹)는 CBM의 핵심 가치인 'Intervention' 메커니즘을 직접 구현한다. 또한 LLM 기반의 자동 라벨링은 Oikarinen et al. (2023)의 Label-free CBM 노선을 자연어 도메인에 차용한 것이다. 이러한 설계 정합성은 (i) 분류 결정에 대한 정량적 근거 제공, (ii) 통계청 분류 담당관의 직접 개입 가능, (iii) ISCO-28 SLF "best fit" 원칙의 알고리즘적 구현 — 의 3가지 정책적 가치를 동시에 만족한다.

### 4.2 발표 자료 1슬라이드 권고

본 연구의 시스템 그림(설계서 §2)에 박석훈 발표자료 p.15 (CBM 구조 도식) 와 같은 형식의 1슬라이드 추가. "통계기준연구회 2026-05-20 발표의 CBM 구조를 자연어·직업분류 도메인에 직접 적용" 한 캡션.
