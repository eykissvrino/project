## 1. 무엇을 하는가 (스코프 — 절대 벗어나지 말 것)
- **목표**: KSCO 8차 세세분류 **1,270 전수** → **TASK → DWA → IWA → GWA** 4계층을 완벽 도출.
- **이번 범위 = Stage 0~4 까지만.** Responsibility 3축·직업 프로파일링·변별력 분석(Stage 5~7)은 **범위 밖**(후속). 손대지 말 것.
- **왜 전수인가**: GWA는 직업·산업을 가로지르는 최상위 일반활동 → 한두 분야로는 무의미. 10개 대분류를 다 덮어야 "KSCO가 ONET 41을 재현하는가" 가설 검증 가능.

## 6. 전수 실행 방식 — 배치 + 이어달리기 (핵심)
- **추출 주체**: Claude Code(=구독 Opus) 본체/서브에이전트가 §1.2 프롬프트 규약대로 KSCO 입력을 읽어 JSON 추출 → `extract_one`→`persist`→DuckDB 적재. **API 호출 없음**(하이브리드 manual 경로).
- **배치 단위**: 세세분류를 **소분류/중분류 묶음**으로 나눠 서브에이전트에 배분. 1,270÷배치 누적.
- **이어달리기**: DuckDB가 체크포인트. 이미 적재된 직업은 `llm_call_log`/`task` 존재로 **skip**(재실행 0회). MAX 5시간 롤링 한도에 끊겨도 **다음 세션에서 남은 직업만 이어서**.
- **규모 경고**: 1,270 × (8~30 심층추출) = **여러 시간·여러 세션**. 한 번에 안 끝남이 정상. 진행률을 직업수 기준으로 보고.
- **안전 권장**: 첫 배치(소수 직업) 적재 직후 **엑셀 1회 검수** → 산출물 모양·추적성 확인 후 나머지 가속. (사용자는 "바로 전수"를 택했으나, 대량 적재 전 첫 배치 눈검수는 결함을 싸게 잡는 안전장치)
