# Stage 1 설계 — TASK 도출 (KSCO 입력 → 직무 행동진술 + 도구 + 환경)

> 단계별 설계 시리즈 #1 · **v1.0 확정(2026-06-01)** — 전수·Opus단독·ONET준거(8~30)·상세추적 결정 반영
> 입력: Stage 0의 "추출가능 입력 레코드" / 출력: TASK·도구·환경
> 원칙: **행동진술(동사+목적어) 판정은 본 단계가 담당**(Stage 0 결정 #2). 도구·환경 동시 추출(결정 #3).

---

## ① 목표·정의
- **목표**: 세세분류별 입력(자기 정의·예시 + 부모 주요업무 상속)에서 **① 직무활동(TASK) ② 사용 도구(Tools) ③ 작업 환경(Work Context)** 3차원을 **동시** 추출.
- **TASK 정의**: "**동사 + 목적어 (+ 수단/맥락)**" 구조의 단일 행동진술. 하나의 TASK엔 **주된 동사 1개**. 한국어 "~한다/~수행한다" 종결.
  - 예: "도면을 검토하여 형태를 확인한다" → verb=검토하다, object=도면.
- **제외**: 직업명·소제목("투자분석 전문가", "고위공무원"), 너무 일반적 진술("업무를 수행한다"), 예시 나열.

## ② 도출 이론 (왜)
- **직무분석 task inventory** + **ONET task statement 규약**(동사+목적어, 단일 주동사) — 표준화된 활동 단위.
- **ONET 2014 정성 기각 → LLM 극복**: ONET은 "당시 NLP가 task 의미 추출 불가"라 자동화 기각. 2026 LLM 의미이해로 그 전제를 깸 → **LLM hybrid**.
- **Self-consistency**(재현성): 동일 입력 2회 독립 실행 + cross-model → 환각·변동 통제. 통계청 "같은 입력 같은 결과" 방어.
- **3차원 동시(C1)**: 업무·도구·환경을 1회 호출로 동시 추출 → 추가비용 0. 단 도구·환경은 **명시 단서만**(근거스팬 필수, 빈값 허용) — KSCO 한계 정직 반영.
- **세세분류+상속(D0)**: 부모 주요업무를 활동 골격으로, 세세분류 정의로 특화(2-pass).

## ③ 입력 → 출력 스키마
**입력**: Stage 0 레코드 — **`추출컨텍스트`(세세정의 + 조상정의 대>중>소>세 결합)** + 상속 적용된 `main_tasks`(출처: 세세분류 자체보유 167 / 세분류 상속 1,027 / **없음 76**) + 자기 예시 + 메타(low_signal·valid).
> ⚠️ **출처 분기 처리**(Stage 0 재구현 반영):
> - 주요업무 **보유**(자체/세분류) → 2-pass(주요업무 골격 → 세세정의 특화).
> - 주요업무 **없음(76, 군인 등)** → 주요업무 골격이 없으므로 **`추출컨텍스트`(세세+조상 정의)만으로** TASK 도출.
> - **빈약 세세정의(low_signal 385)** → 반드시 `추출컨텍스트`의 조상정의를 함께 투입(세세정의 단독 추출 금지).
**출력 3종**
```
task: {task_id=T_{code}_{seq}, ksco_code(5자리), parent_code, verb, object,
       full_statement, source_sentence, layer, source, source_subject,
       confidence, extraction_runs, cross_consistency, low_signal}
tool_inventory: {tool_id, ksco_code, name, category(HW/SW/도구/장비/시스템),
       evidence_span, confidence}
work_context: {context_id, ksco_code, category(장소/위험/사회적/신체적/시간적),
       value, evidence_span, confidence}
```

## ④ 도출 방법 (절차)
1. **규칙 1차 + 행동진술 판정**: 입력 글머리/문장에서 "~다" 종결·동사+목적어 형태만 후보로(직업명·소제목 제외 = Stage 0 결정 #2 실행 지점).
2. **Opus 심층 추출(3차원 동시, ONET 준거 8~30·상한 40)**: §1.2 프롬프트로 task·tools·work_context를 JSON 출력. **직업당 TASK는 ONET 실측 분포(중앙값 20·90%ile 30·최대 40)를 준거로 충실히 추출하되 상한 40 내**. 8 미만은 정보부족으로 `remarks` 비고, 40 초과는 과추출 점검. *(이전 "개수 제한 없음/무제한"은 폐기 — §7·§8-2와 통일.)*
   - **2-pass 특화**: (Pass1) 상속 주요업무로 활동 골격 → (Pass2) 세세분류 정의·예시로 목적어 구체화·고유활동 추가·무관 제거.
   - **주요업무 없음(76) 분기**: Pass1 골격이 없으므로 `추출컨텍스트`(세세+조상 정의)에서 직접 활동을 도출. 빈약 세세는 조상정의로 보강.
3. **Self-consistency (Opus 2회 독립 실행, GPT 없음)**: 동일 입력 **2회 독립 실행**(구독 Opus는 OpenAI식 `seed` 파라미터 없음 — temperature 변동 기반) → **합집합 채택**(둘 중 하나라도 나온 TASK 포함 = 최대 도출), 둘 다 나온 TASK는 confidence↑. **cross-model 비교 안 함**(Opus 단독).
4. **도구·환경**: 명시 단서 있을 때만, 근거스팬 부착, 없으면 빈 배열. (사무직 도구 약함 = 정상)
5. **도출 과정 기록(★ 상세 추적)**: 각 TASK에 `source_sentence`(원문 근거) + `derived_from`(상속 주요업무/세세정의/조상정의 어디서 특화됐는지) 기록 → **엑셀만 봐도 "이 TASK가 어디서 어떻게 나왔는지" 추적 가능**.
6. **정규화·중복제거·적재**: 동의어 lexicon 정규화 → **의미 중복 병합**(합집합 후 bge-m3 코사인 ≥ ~0.9 near-dup 통합; L0 우선 보존) → task/tool_inventory/work_context 적재(트랜잭션) + `llm_call_log` 캐시.
   > C3: 합집합은 의역 중복을 늘려 Stage 2 군집을 오염시키므로, **임베딩 기반 near-dup 병합을 TASK 단계에서 선행**(임베딩은 어차피 Stage 2 입력). 단순 lexicon만으론 부족.

## ⑦-2 산출 지표 확정 정의 — 정의빈약·신뢰도·일관성 (전수 결과 반영)
> **as-implemented**(`pipeline/s1_extract.py`·`dedup.py`·`s0_preprocess.py`) 기준 확정 정의. 엑셀 산출물·DB의 해당 컬럼을 그대로 설명한다. 수치는 **전수 1,270직업·16,168 TASK** 기준.

### (1) 정의빈약 `low_signal` (TRUE/FALSE) — 세세분류 단위
- **무엇**: 해당 세세분류(5자리)가 KSCO 해설서에 가진 **자기 정의 텍스트가 빈약한지**를 Stage 0에서 자동 판정한 플래그.
- **판정 기준**(둘 중 하나라도 해당 → **TRUE**): ① 자기 정의 길이 **< 50자**, 또는 ② 정의의 **영문·기호(ASCII) 비율 > 0.45**(한글 설명이 거의 없음).
- **의미**: `FALSE` = 자기 정의가 충실(직업 정의만으로 추출 근거 풍부) / `TRUE` = 자기 정의가 빈약(짧거나 영문·코드 위주).
- **추출에 미치는 영향**: `TRUE`인 직업은 **세세정의 단독 추출을 금지**하고, 반드시 **상위 위계(세>소>중>대)의 조상정의를 함께 투입**해 보완 추출한다(§3·§4-2). 직업 고유 특화 신호가 약하면 무리하게 창작하지 않으므로 TASK 수가 적게(부족<8) 나올 수 있다.
- **전수 결과**: **TRUE 385직업 / FALSE 885직업**. 부족(<8) 128직업은 대체로 이 `TRUE` 군(관리·단순노무·일부 기능직)에 분포 — 정직한 과소추출(후속 비고 처리).

### (2) 신뢰도 `confidence` (0.80 / 0.95) — TASK 단위
- **무엇**: 각 TASK의 신뢰도. **2회 독립 추출의 교차 일치(cross-run agreement)** 로 산정한다(LLM이 추출 시 매긴 자체 점수가 아님).
- **산식**: 동일 `(동사, 목적어)` TASK가
  - **2회 모두 출현 → `0.95`** (양런 일치 = 높은 신뢰)
  - **1회만 출현 → `0.80`** (단런 = 합집합으로 포함하되 신뢰 보정)
- **근거**: 동일 입력 2회 독립 실행(self-consistency) 후 **합집합 채택**(누락 최소화) + **둘 다 나온 TASK는 신뢰도↑**(§4-3). LLM 자체 confidence는 near-dup 병합 시 대표 선택의 보조 기준(tiebreaker)으로만 사용.
- **전수 결과**: `0.95`(양런 일치) **8,359건(51.7%)** / `0.80`(단런) **7,809건(48.3%)**. → 전체 TASK의 **절반 이상이 두 독립 추출에서 동시 확인**된 강건한 결과.

### (3) 일관성 `cross_consistency` (0~1, Jaccard) — 직업 단위
- **무엇**: 같은 직업을 **두 번 독립 추출했을 때 결과가 얼마나 겹치는가**(재현성·self-consistency 지표). 직업당 1개 값.
- **산식**: 두 독립 추출의 `(동사, 목적어)` 집합 간 **Jaccard 유사도** = |교집합| / |합집합|.
- **전수 결과**: **중앙값 0.412 · 평균 0.428 · 범위 0~1**.
- **해석 주의**: 정확 `(동사,목적어)` 문자열 일치 기준이라 **같은 활동을 다른 표현으로 적으면 낮게** 집계된다(합집합 채택으로 커버리지 손실은 없음). 정의가 풍부한 직업군일수록↑, 정의빈약(`low_signal=TRUE`) 직업군일수록 조상정의 기반 변이가 커져↓ 경향. → 통계청 "같은 입력 같은 결과" 방어용 **투명성 지표**이며, 낮다고 품질 저하가 아니라 표현 변이를 그대로 드러낸 값.

> **세 지표의 관계**: 정의빈약(TRUE)일수록 → 조상정의 의존↑ → 추출 변이↑ → 일관성(Jaccard)↓·단런(0.80) 비중↑ 경향. 세 컬럼을 함께 보면 "이 직업의 추출이 얼마나 탄탄한 근거에서 나왔는지"를 추적할 수 있다.

## ⑧ 핵심 설계 결정 (확정)
1. **전수 추출 운용**: → **전수(1,270) + Claude Opus 4.8 단독(구독, API/GPT 없음)**, Claude Code 서브에이전트 배치 오케스트레이션. (규모상 누적 진행)
2. **개수 범위(ONET 준거)**: → ONET 실측(923직업·18,796 TASK, 중앙값 20·90%ile 30·최대 40) 근거로 **직업당 8~30 목표, 상한 40**. *무제한 폐기*. 충실히 뽑되 40 초과 시 과추출 점검, 8 미만은 정보부족으로 `remarks` 비고 표기. 2회 독립 실행 합집합으로 누락 최소화하되 상한 내에서.
3. **상세 추적**: → 각 TASK에 source_sentence·derived_from 기록, **엑셀만 봐도 도출 과정 이해 가능**하게.
4. **규칙 1차 필터**: → "~다 종결 + 동사 형태소" 2중 필터로 직업명·소제목 차단(채택).
5. **도구·환경 카테고리**: 도구 HW/SW/도구/장비/시스템, 환경 장소/위험/사회적/신체적/시간적(잠정 채택, Stage 1 운영 중 조정).
