# 전체 구조 & 군집 방법 선정 (Stage 설계의 토대)

> v0.1(검토 전) · 목적: ① 직업↔TASK↔DWA↔IWA↔GWA가 어떻게 연결·구조화되는지 ② 최종 산출(직업별 프로파일·GWA 중요도·분석) ③ 군집 방법을 *비교 평가*하여 선정 근거 확보.

---

## A. 전체 구조 — 두 축으로 나눠 본다

본 프로젝트는 사실 **두 개의 다른 일**을 한다. 섞으면 혼란하다.

### 축 1) 활동 어휘 체계 도출 (taxonomy, 상향식·전 직업 공통)
```
전체 TASK ─(군집)→ DWA ─(군집)→ IWA ─(추상화)→ GWA
```
= 한국 직업 전체에서 통용되는 **작업활동 "사전"**(공유 어휘). 직업과 무관한 *공통 체계*.

### 축 2) 직업 프로파일링 (직업별, 체계에 매핑)
```
직업(세세분류) ─보유→ {TASK들} ─매핑→ DWA → IWA → GWA
  → 직업 × (DWA/IWA/GWA) "보유·중요도" 프로파일
```
= 각 직업이 위 어휘 체계의 어느 활동을, 얼마나(중요도) 수행하는가.

### 연결(데이터 모델)
| 관계 | 카디널리티 | 의미 |
|---|---|---|
| 직업 → TASK | 1 : N | 직업이 가진 작업들 |
| TASK → DWA | N : 1(~3) | TASK가 속한 상세활동(Multiple Linkage ≤3) |
| DWA → IWA → GWA | N:1, N:1 | 단일 트리 nesting(상위 추상) |
| **직업 → GWA** | N : M | TASK 체인을 타고 올라간 **프로파일**(중요도 가중) |

> 핵심: **GWA는 "직업 위에 붙는 라벨"이 아니라, 직업의 TASK들이 체계를 타고 올라가 형성하는 프로파일**이다. 그래서 "직업별 GWA 중요도"를 측정·분석할 수 있다(축 2).

### A-2. 최종 구조 = "얽힌 네트워크" (ONET 실측 근거)
ONET 데이터를 직접 분석한 결과, 구조는 **깨끗한 트리가 아니라 부분적으로 얽힌 네트워크**다.

| 관계 | 구조 | ONET 실측(29.3) |
|---|---|---|
| **TASK → DWA** | **Multiple Linkage(다대다 = 얽힘)** | 18,495 task → 23,233 링크, **평균 1.26·최대 3** (단일 78%·2개 19%·3개 3%) |
| **DWA → IWA → GWA** | **Strict tree(사후매핑 불필요)** | DWA→IWA 다중매핑 **0건** = 완전 트리 |
| **직업 → GWA** | 다대다 프로파일 | 직업당 ~20 task → 여러 DWA → 여러 GWA |

→ **백본(DWA-IWA-GWA)은 단일 트리(방법 A), TASK는 Multiple Linkage(≤3)로 백본에 엮임, 직업은 여러 GWA에 걸침.** 이 두 지점이 "얽힘"을 만든다.

```
 직업 ─(1:N)─ TASK ═(Multiple Linkage ≤3, 평균~1.3)═▶ DWA ─┐
                                                            │ strict tree
                                                           IWA ─┤
                                                                GWA
 = 백본 트리 + TASK 다중연결 + 직업 다중 GWA  →  최종 그림 = 네트워크
```

**시각화(논리 방어용)**: dendrogram(백본 트리) + **Sankey/네트워크 다이어그램**(직업-TASK-DWA-IWA-GWA 흐름) + 직업×GWA 히트맵. → "얽힌 그림"을 그대로 표현.

### A-3. 레벨별 명명 규약 (ONET 실데이터 확인)
| 레벨 | 풀네임 | ONET 형태 | 한국어 규칙 | 예 |
|---|---|---|---|---|
| GWA | Generalized Work Activities | **명사형** ("Getting Information") | 명사형 일반활동 | "정보 입수" |
| IWA | **Intermediate** Work Activities | 동사구·일반 ("Read documents or materials to inform work") | 동사구·일반(여러 DWA 포괄) | "문서·자료를 읽어 업무에 활용한다" |
| DWA | Detailed Work Activities | 동사구·상세 ("Read maps to determine routes") | 동사구·상세 | "경로 파악을 위해 지도를 읽는다" |
→ IWA·DWA는 둘 다 동사구, **차이는 목적어의 일반성**(DWA 구체 ↔ IWA 포괄). GWA만 명사형.

## B. 최종 산출 & 분석 (연구 목적과 직결)

1. **직업별 4계층 프로파일**: 직업마다 TASK 목록 → 각 TASK의 DWA/IWA/GWA → 직업의 GWA 분포.
2. **GWA 중요도 측정**: 직업 o의 GWA g 중요도 = (g로 가는 TASK 비중) 등 텍스트 기반 프록시.
   - ⚠️ 정직: ONET의 Importance·Level은 *재직자 설문* 산출. 우리는 설문이 없어 **TASK 빈도·비중 기반 프록시** + **Responsibility 3축(level 유사 차원)**로 근사.
3. **분석(목적 직결)**:
   - 직업 간 프로파일 유사도 → **직업 전환 가능성**(목적 #3)
   - 같은 KSCO 코드 내 직업 프로파일·R점수 격차 → **변별력·분기 후보**(목적 #1)
   - 한국 GWA ↔ ONET GWA 정합 → **국제 정합성**(목적 #2)

### 확장된 단계 맵 (구조 반영)
```
Stage 0 입력·전처리
Stage 1 TASK 도출            ┐
Stage 2 DWA 도출 (군집)      │ 축1: 어휘 체계 도출(상향식)
Stage 3 IWA 도출 (군집)      │
Stage 4 GWA 도출 (추상화)    ┘
Stage 5 직업 프로파일링       ← 축2: 직업 × DWA/IWA/GWA 매핑·중요도  [신규 명시]
Stage 6 Responsibility 3축    ← level 유사 차원(관리·감독·안전)
Stage 7 분석·검증            ← 변별력·직업전환·ONET 정합
```

## C. 군집 방법 비교·선정 (이게 최선인가?)

### 본 연구의 군집 요구사항
- **R1 계층 nesting**: DWA⊂IWA⊂GWA가 일관(같은 DWA는 반드시 같은 IWA·GWA).
- **R2 전배정**: 모든 TASK·직업이 어딘가에 속함(고아 없음 — 직업 프로파일이 비면 안 됨).
- **R3 재현성**: 결정론적(통계청 "같은 입력 같은 결과").
- **R4 해석·ONET비교**: 군집이 해석 가능, ONET과 매핑 가능.
- **R5 스케일**: 전수 ~1~3만 TASK 처리.

### 방법별 평가
| 방법 | R1 nesting | R2 전배정 | R3 재현성 | R5 스케일 | 종합 |
|---|---|---|---|---|---|
| **계층적 응집군집**(average/Ward·코사인) | ◎ 단일트리 | ◎ | ◎ 결정론 | △ O(n²)메모리 | **최적** |
| HDBSCAN(밀도) | △ 3계층 약함 | ✗ **노이즈 다수**(우리 실측 38~62% 미배치) | △ 민감/UMAP시 비결정 | ◎ | 부적합 |
| K-means/구면 | ✗ 평면·k지정 | ◎ | ○ | ◎ | 계층X |
| 그래프 커뮤니티(Louvain/Leiden, 다해상도) | ○ 다해상도 | ◎ | △ | ◎ | **대안후보** |
| BERTopic(UMAP+HDBSCAN+cTF-IDF) | △ | ✗ 노이즈 | ✗ UMAP 확률적 | ◎ | 부적합(명명 아이디어만) |

### 결론·근거
- **계층적 응집군집이 최적**: R1·R2·R3(계층 nesting + 전배정 + 재현성)을 *동시에* 만족하는 유일한 방법. ONET식 분류체계·taxonomy induction의 표준.
- **HDBSCAN 부적합 이유**: ① 노이즈(-1)로 직업 프로파일에 구멍 → 축2 붕괴 ② 3계층 의미 nesting을 안 줌 ③ (UMAP 결합 시) 비결정 → R3 위반. *우리가 이미 실측으로 38~62% 미배치를 봄.*
- **스케일(R5) 보완**: 전수가 무거우면 **2단계 하이브리드** — (1) 미니배치 k-means로 micro-cluster 수천 개 → (2) 그 centroid로 응집군집(계층). 확장성+계층 둘 다 확보.
- **대안**: 그래프 커뮤니티(Leiden)는 다해상도가 계층과 친화 → 응집군집과 **실증 비교 후보**.

### 권고: 이론 채택 + 실증 검증 병행
1. **이론적 1순위 = 계층적 응집군집**(필요 시 2단계 하이브리드).
2. **실증 벤치마크**(시범 중분류 28 등): 응집군집 vs HDBSCAN vs Leiden을 **지표로 비교** — 실루엣·군집 응집도·고아율·ONET 정합·전문가 해석성 → 데이터로 최종 확정. "이게 최선" 주장을 *근거*로 뒷받침.

## 확정 결정 (2026-06-01)
1. **군집 방법 = 계층적 응집군집**(평균/Ward·코사인). 스케일 시 2단계 하이브리드(미니배치 k-means→응집). dendrogram·실루엣 등 시각화·논리방어 확보.
2. **GWA 도출 = 하이브리드(주) + 순수 상향식(탐색)**:
   - **(주) 하이브리드 = ONET 실제 방식**: GWA = **ONET 41(한국어 번역)을 상위 어휘로 채택**, KSCO에서 TASK→DWA→IWA **상향식 도출** → **IWA→GWA 매핑**. → 정보처리·추론/정신활동/업무수행 등 **ONET 형태 GWA 보장**.
   - **(탐색) 순수 상향식**: KSCO만으로 GWA까지 도출 → "ONET과 몇 % 일치"를 별도 비교(학술 기여, 가설 검증).
3. **스코프 = Stage 0~4(TASK·DWA·IWA·GWA 완벽 도출)에 집중.** Stage 5(프로파일링)·6(R3축)·7(분석)·GWA중요도는 **보류**(본 작업 범위 밖).
4. **GWA 중요도·프로파일링**: 후속 단계 — 지금 설계 안 함.

> ※ §B의 확장 단계맵(5~7)·축2 프로파일링은 **참고용 미래 구조**로만 둔다. 현 작업은 축1(어휘 체계 도출 0~4)만.
