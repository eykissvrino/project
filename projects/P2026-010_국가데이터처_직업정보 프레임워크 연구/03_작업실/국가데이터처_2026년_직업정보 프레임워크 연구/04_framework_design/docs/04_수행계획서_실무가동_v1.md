### 2.2 우선순위 — 이번 주(2026-05-29 ~ 06-04) 착수 항목

1. **작업 0.1 + 0.2 동시 진행** (Claude Code 안에서 PDF/hwpx 파싱 코드 한 번에 작성·실행)
2. **작업 0.4 (kfw init + ingest ksco)** — DDL은 이미 있으므로 Phase 0 안에 완료
3. **작업 0.5 (KECO 연계표)** — xlsx이라 가장 단순, 빠르게 처리

→ 0.6~0.8은 Phase 1 도구 개발과 병행 가능 (모든 자료가 Layer 0 = KSCO 만으로 일단 가동 가능하기 때문)

### 2.3 검수 기준 (모든 0.x 산출물 공통)

- 한자·특수문자·OCR 오류율 < 1%
- 컬럼 명세는 `11_DuckDB_스키마_DDL.sql`와 1:1 일치
- 모든 import 결과는 row count·null rate·sample 5건을 검수 로그 (`01_data_collection/processed/_import_log.md`) 에 남김

## 3. Phase 1 — AI 도구 개발 (kfw CLI 실구현)

**현황**: `03_NLP_analysis/scripts/cli/kfw.py` 에 18개 명령이 정의돼 있으나 14개가 `logger.info(...TODO...)` 상태. 본 Phase에서 핵심 6개를 실구현한다.

### 3.1 개발 우선순위

| 우선 | 명령 | 구현 내용 | 차원 트랙 | 의존 |
|---|---|---|---|---|
| **1** | `kfw run preprocess` | Mecab-ko + Kss 4 + 동의어 사전 적용. KSCO 정의·주요업무 텍스트 → 문장 단위 parquet | 공통 | Phase 0.4 |
| **2** | `kfw run extract-tasks` | **LLM 호출 코어**. Claude Opus 4 (또는 Claude Code 내장 Claude) + GPT-5 self-consistency 2회. 출력: `tasks.parquet` | **업무·도구·환경 동시 추출** (C1 결정) | 1번 |
| **3** | `kfw run jf-split` | Job Family 분할 (KECO 중분류 기준) — task에 `job_family_id` 부여 | 공통 | 2번 |
| **4** | `kfw run gwa-bucket` | ONET 41 GWA zero-shot LLM 할당, 2회 일치성 | 업무 | 2·3번 + Phase 0.7 |
| **5** | `kfw run cluster-dwa` | bge-m3 임베딩 + HDBSCAN + 8조항 라이팅 | 업무 | 4번 |
| **6** | `kfw run score-resp` | Responsibility 3축 0-3점 + 근거 스팬 | R3축 | 2번 |

`dwa-qc` · `cross-family-dwa` · `multi-linkage` · `cluster-iwa-kr` · `map-iwa-gwa` 는 Phase 2 진입 후 구현 (파일럿 데이터로 검증하면서).

### 3.2 도구·환경별 개발 분담

| 작업 | 주 도구 | 보조 도구 | 비고 |
|---|---|---|---|
| 프롬프트 작성·튜닝 | **Claude Code** (본 Cowork 환경) | 별도 외부 API 없음 | 단일 직업 입력으로 프롬프트 빠르게 반복 개선 |
| Python 코드 작성·디버그 | Claude Code | VS Code · Cursor | `03_NLP_analysis/scripts/` 에 모듈 추가 |
| 단위 테스트 | pytest | Claude Code | 각 명령당 최소 3개 케이스 (정상·경계·실패) |
| LLM 호출 — 개발 시 | **Claude Code 안의 Claude 직접 사용** | — | API 비용 0 |
| LLM 호출 — 배치 시 | **Anthropic API (Opus 4)** + OpenAI API (GPT-5 cross-check) | seed=0 / temp=0 + prompt hash 기록 | `results/cache/` 에 호출 결과 보관 |
| 임베딩 | sentence-transformers/bge-m3 (로컬) | GPU 가능 시 활용 | 1회 임베딩 후 재사용 |
| 군집 | hdbscan (로컬) | — | min_cluster_size 파일럿에서 튜닝 |
| 데이터 저장 | DuckDB 단일 파일 | Parquet 스냅샷 | 모든 중간 결과는 Parquet으로도 백업 |

### 3.3 단계별 DoD

- **명령 1·2 완료 시**: 단일 KSCO 코드(예: 28201 경영지원 사무원) 입력 → JSON task 10±건 출력, source 메타 보존
- **명령 4 완료 시**: 동일 KSCO 코드의 task 10건에 GWA 41 중 하나씩 할당, 2회 실행 일치율 ≥ 0.80
- **명령 5 완료 시**: 군집 ≥ 2개, 각 군집에 8조항 위반 없는 DWA 라벨
- **명령 6 완료 시**: R3축 점수 0-3 + 근거 스팬 텍스트 추출

## 4. Phase 2 — 테스트 및 시범적용 검증

### 4.1 Step A — 단일 직업 E2E (가장 중요한 게이트)

**대상**: KSCO 28201 (가칭: 경영지원 사무원) 또는 사용자 선택 1개
**작업**: Phase 1 명령 1~6을 순차 실행, 단일 직업 1건에 대해 TASK→DWA→R 출력
**DoD**:
- 추출된 task 8~15건
- DWA 군집 3~5개, 8조항 100% 준수
- R 3축 점수 + 근거 스팬 모두 존재
- 전체 파이프라인 1회 실행 시간 < 10분 (1직업 기준)

→ **이 단계가 통과해야 Step B 진입.** Phase 1 도구의 통합 동작 검증이 본 단계의 핵심.

### 4.2 Step B — 중분류 28 (경영·금융) 약 20 세분류

**작업**:
- 배치 실행 (20 세분류 × 직업당 평균 12 task = 약 240 task)
- 전문가 5인 중 **경영·HR 분야 위원 2명**이 노션 또는 구글시트로 1차 검토
- 변별력 핵심 지표 측정: 관리책무성 점수 분산 (Gini), 같은 코드 내 직업사전 직업명별 R점수 분포

**DoD**:
- 240 task 중 전문가 채택율 ≥ 0.65
- "치킨집 사례" 형 분기 후보 자동 플래그 동작 확인
- HumRRO 임계 (relevance 60% / importance 3.0) 측정 가능

### 4.3 Step C — 중분류 22 (정보통신) 약 18 세분류

**작업**: Step B와 동일 절차, 단 **신생직업 변별**과 **도구 차원** 충실도 검증에 초점
- KECO 2025 신설 53개 직업 중 22 중분류 해당 항목 우선 검증
- 도구·환경 차원: 추출된 도구 키워드의 구체성 검사 (너무 일반 "컴퓨터" vs 충분히 구체 "IDE")

**DoD**:
- 신생직업 task 추출 완성도 (KSCO 정의 부족 시 L1 직업사전 트리거 동작 확인)
- DWA 임계 4/3 vs 3/2 양쪽 결과 비교 → 한국화 임계 확정 (Action G9 해결)

### 4.4 Step B·C 종료 후 결정사항

- DWA 임계 (4/3 vs 3/2) **확정**
- LLM 비용·시간 실측 → Phase 3 전수 가동 비용 추산
- 전문가 검토 병목 측정 → Streamlit 가동 시점 확정
- 평가지표 9종 1차 값 → 보고서 본문 1차 안에 인용 가능

## 5. Phase 3 — KSCO 495 전수 가동 (M+5 이후)

본 단계는 Phase 2 결과 반영 후 별도 v2 수행계획으로 상세화. 본 v1에서는 골격만:

- **배치 분할**: KECO 중분류 24개 단위 (Job Family 단위 = ONET 원안)
- **검토 큐 우선순위**: R 점수 ≥ 2 직업 + 신뢰도 하위 30% task 우선
