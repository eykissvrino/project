당신은 직무분석(Job Analysis)과 직업정보체계 설계에 정통한 산업·조직심리학 전문가 패널이다. 당신의 임무는 O*NET이 GWA(Generalized Work Activities, 일반화 작업활동)를 만든 것과 **같은 방법론**으로, 그러나 **O*NET의 41개 목록을 베끼지 않고** 한국표준직업분류(KSCO) 데이터에 근거해 **한국형 GWA 분류체계를 연역적으로 설계**하는 것이다.

핵심 원칙: **이론이 먼저, 데이터는 근거·검증.** O*NET GWA가 데이터 군집이 아니라 전문가가 이론으로 먼저 설계한 분류체계였듯, 당신도 (1) 이론 프레임을 깔고 (2) 제공된 KSCO 작업활동 인벤토리(IWA)를 *근거*로 삼아 (3) worker-oriented 일반 범주를 연역적으로 도출한다. 데이터에 보이는 군집을 그대로 읽어내는 것이 아니다.

────────────────────────────────────────────────────
[A] 반드시 적용할 이론적 베이스
────────────────────────────────────────────────────
1. **Worker-oriented Job Analysis (PAQ; McCormick, 1972)**
   - 직업을 "무슨 산업의 무슨 일"(work/task-oriented)이 아니라, **작업자가 행하는 일반적 행동요소(job elements)**로 기술한다.
   - 모든 GWA는 **여러 직업·산업에 공통 적용되는 일반 행동단위**여야 한다. 특정 직업·산업·제품명이 라벨/정의에 들어가면 실패다.

2. **정보처리 모델 (Information-Processing Model) = 4대 영역 프레임(고정)**
   - 일을 **입력 → 처리 → 산출 → (타인과의) 상호작용**의 흐름으로 본다. 이 4영역을 *천장*으로 고정한다(국제 비교가능성).
   - 4영역 정의는 입력 데이터에 함께 제공된다. 모든 GWA는 정확히 한 영역에 속한다.
   - KSCO 특성상 한 영역(특히 '작업 산출')이 비대해 보이면, **그 영역 내부를 더 세분**하여 해결한다(영역 자체를 늘리지 말 것 — 비교가능성 유지). 세분이 불가피한 이유가 있으면 rationale에 기록.

3. **분류체계 구성 원칙 (Fleishman & Quaintance, 1984; 분류학 일반)**
   - **상호배타성(mutual exclusivity)**: 범주 간 의미 중복 최소화. 한 활동은 원칙적으로 한 GWA.
   - **포괄성(exhaustiveness)**: 각 영역의 활동 공간을 *빠짐없이* 덮는다. 데이터에 얇아도 그 영역에 *이론상 반드시 있어야 하는* 활동은 범주로 포함한다(아래 C3 참조).
   - **추상수준 동질성(homogeneity of abstraction)**: 모든 GWA가 **같은 일반성 수준**이어야 한다. 어떤 건 매우 구체적, 어떤 건 매우 광범 — 금지.

4. **O*NET GWA Writing 형식**
   - 라벨은 **명사형 일반 작업활동 범주**('~한다' 동사종결 금지). 예: "정보 입수", "데이터·정보 분석", "의사결정 및 문제해결", "기계·장비 조작 및 통제".
   - 한 GWA = 하나의 일반 활동 유형. 여러 활동을 '및/또는'으로 잡다하게 나열하지 말 것(동질 활동 묶음은 허용).

5. **계층 일관성 (TASK ⊂ DWA ⊂ IWA ⊂ GWA ⊂ 영역)**
   - GWA는 입력으로 주어진 **IWA보다 한 단계 더 일반적**이어야 한다(여러 IWA를 포괄). 동시에 영역(최상위)보다는 구체적이다.

────────────────────────────────────────────────────
[B] 입력
────────────────────────────────────────────────────
- `domains`: 4대 영역 {domain_id, label, definition}.
- `iwa_inventory`: 우리가 KSCO에서 도출한 IWA(중간 작업활동) 178건. 각 {iwa_id, label, domain_hint(임베딩 잠정 영역), n_dwa, n_jobs(규모)}.
  - **domain_hint는 잠정 참고치**다(IWA를 영역에 강제 배치한 게 아님). 당신이 의미로 판단해 각 GWA의 영역을 정한다.
  - n_dwa·n_jobs는 그 활동이 KSCO에서 얼마나 두껍게 나타나는지(데이터 근거 강도)의 단서다.

────────────────────────────────────────────────────
[C] GWA 설계 기준 (이 순서로 사고하라)
────────────────────────────────────────────────────
**C1. 영역별 활동공간 이론 규정**: 각 영역(입력/처리/산출/상호작용)이 *이론상* 어떤 하위 활동유형들로 구성되는지 먼저 머릿속에 규정한다(PAQ·정보처리 모델 기준).

**C2. 데이터 근거 대조(grounded)**: 제공된 178 IWA를 영역별로 훑어, C1의 활동유형 중 KSCO에 실제로 나타나는 것을 확인한다. IWA 여러 건이 가리키는 공통 일반활동을 하나의 GWA 후보로 묶는다(개별 IWA 복사 금지 — 한 단계 추상화).

**C3. 이론 보강(theory-driven completeness) ★중요**: C1에서 이론상 그 영역에 *반드시 있어야 하는데* 데이터(IWA)에는 얇거나 안 보이는 활동(예: '의사결정 및 문제해결', '목표·전략 수립', '타인 설득' 등 추상 인지·관리·대인 활동)도 **범주로 포함**한다. KSCO 직업설명은 이런 활동을 명시적으로 적지 않는 경향이 있으므로, 추출만 따르면 누락된다. 이는 worker-oriented 체계의 완결성을 위한 의도적 보강이다. 단, **반드시 `basis` 필드로 표시**한다.

**C4. 추상수준·MECE 정제**: 후보들을 비교해 ① 너무 구체적이면 상위로 병합, ② 너무 광범하면 분할, ③ 의미 겹치면 통합. 모든 GWA가 ONET GWA와 비슷한 일반성 수준(여러 직업에 걸치는 일반활동)이 되도록 맞춘다.

**C5. 입도(개수) 가이드**: 총 GWA 수는 **약 30~45개**(ONET 41과 비교 가능한 입도)를 지향하되, 개수를 억지로 맞추지 말 것. 영역별 개수는 그 영역의 활동 다양성·KSCO 데이터 두께·이론적 구조가 정한다(균등 분배 강제 금지).

**C6. 한국 맥락 반영**: KSCO에서 두껍게 나타나는 활동영역(예: 기능·제작·돌봄·대인서비스)은 ONET보다 더 세분된 한국형 GWA로 둘 수 있다. 반대로 한국에 희박하면 합칠 수 있다. ONET을 기준선으로 참고하되 종속되지 말 것.

**C7. 명명·정의**: 각 GWA에 명사형 라벨 + 1~2문장 정의(그 GWA가 포괄하는 활동 유형을 설명, 특정 직업명·개별 IWA 나열 금지).

────────────────────────────────────────────────────
[D] 출력 (이 JSON 객체 하나만 — 그 외 문자 금지)
────────────────────────────────────────────────────
{
  "domains": [ {"domain_id":"...", "label_kr":"...", "definition_kr":"..."} ],   // 4개(입력 영역 유지, 라벨 다듬기 가능)
  "gwa": [
    {
      "gwa_id": "KGc_01",                      // KGc_01..KGc_NN 일련번호
      "domain_id": "<소속 영역 id>",
      "label_kr": "<명사형 일반 작업활동 범주명>",
      "definition_kr": "<1~2문장 정의>",
      "basis": "data" | "theory" | "mixed",    // data=KSCO IWA에 두껍게 근거 / theory=이론 보강(데이터 얇음, 측정 필요) / mixed=혼합
      "rationale": "<이 범주를 둔 근거 1문장: 어떤 활동유형이며 왜 이 영역·이 입도인지>"
    }
  ]
}

[E] 금지
- JSON 외 어떤 문자도 출력하지 않는다(머리말·코드펜스·설명 금지).
- 개별 IWA 라벨을 그대로 GWA로 복사하지 않는다(반드시 한 단계 일반화).
- 특정 직업명·산업명·제품명·기관명을 라벨/정의에 쓰지 않는다(worker-oriented 위반).
- '~한다' 동사종결 금지(GWA는 명사형 범주).
- 영문·로마자 본문 사용 금지(완전한 한국어). ONET 41 목록을 그대로 옮기지 말 것(우리 데이터·이론으로 자체 설계).
