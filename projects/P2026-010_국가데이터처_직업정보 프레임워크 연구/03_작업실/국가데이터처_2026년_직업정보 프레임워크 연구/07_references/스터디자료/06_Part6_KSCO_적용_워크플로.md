# Part 6. KSCO 적용 워크플로 — 직업설명자료 → TASK → DWA → GWA

## 학습 목표

1. KSCO 8차 분류항목표의 **직업설명 텍스트 구조**를 이해하고 파싱할 수 있다.
2. 직업설명에서 **TASK 후보를 추출**하는 LLM prompt와 후처리 절차를 설계할 수 있다.
3. 추출된 TASK를 **GWA 41개로 자동 분류 → DWA 군집화 → IWA 묶기**의 흐름을 실제 직업 예시로 따라갈 수 있다.
4. 한 직업의 **직무기술 정의서 1편**을 처음부터 끝까지 완성할 수 있다.

---

## 6.1 KSCO 8차 직업설명 텍스트 구조

### 6.1.1 분류항목표 HWPX의 구조

KSCO 8차 분류항목표는 hwpx 파일로 제공되며, 직업별로 다음과 같은 구조의 텍스트를 포함합니다.

```
[직업 코드]      2491
[직업명]         간호사
[직업 정의]      병원, 의원 등의 의료기관에서 의사와 함께 환자를 진료하고
                 간호하는 업무를 수행한다. 환자의 상태를 관찰하고 의사에
                 게 보고하며, 처방된 약물·치료·검사 등을 수행하고, 환자
                 와 가족의 정신적·정서적 지지를 제공한다.

[주요 업무 예시]
 - 환자 상태 관찰 및 활력징후 측정
 - 의사 처방 약물 투여 및 주사 시술
 - 환자 차트 작성 및 의료기록 관리
 - 환자·보호자 교육 및 상담
 - 응급상황 대응 및 응급처치

[직업 분류 근거]
 - 직능수준: 4 (학사 이상)
 - 직능유형: 보건 전문
 - 사용 도구·장비: 의료기기, 전자차트시스템
```

> **실제 KSCO 8차 hwpx는 위 구조와 다소 다를 수 있으나, 일반적으로 ① 직업명·코드 ② 직업 정의 ③ 주요 업무 예시 ④ 분류 근거를 포함합니다.**

### 6.1.2 텍스트 분량의 한계

- 평균 직업 1개당 100~300자 분량
- 주요 업무 예시는 보통 3~7개 항목
- **이 정도 분량으로는 직접적인 TASK·DWA 도출이 불충분**
- 따라서 보조 데이터원(KNOW·NCS·KECO·한국직업사전)이 필수

### 6.1.3 보조 데이터원의 통합

본 연구가 활용해야 할 한국 직업정보 데이터:

| 데이터원 | 단위 | 분량 | 주요 정보 |
|---------|-----|-----|---------|
| KSCO 8차 분류항목표 | 직업 (세분류 495 + 세세분류 1,270) | 100~300자/직업 | 정의·주요업무·분류근거 |
| **한국직업사전** | 직업 (약 6,000개) | 500~2,000자/직업 | 상세 직무 기술 |
| **KNOW 워크넷** | 직업 (약 537개) | 다차원 정보 | 능력·지식·직업가치 |
| **NCS** | 직무능력단위 | 단위별 1~3쪽 | 능력단위·수행준거 |
| **KECO 직업정보** | 직업 (약 200개 상세) | 500~1,500자/직업 | 직업 안내 |

### 6.1.4 직업 매핑

각 데이터원의 직업을 KSCO 8차 세분류에 매핑하는 것이 첫 단계입니다.

```
KSCO 세분류 "간호사" (2491)
   │
   ├── 한국직업사전 매핑
   │     - 간호사 (직업사전 ID xxx)
   │     - 가정전문간호사 (ID xxx)
   │     - 노인전문간호사 (ID xxx)
   │     ...
   │
   ├── KNOW 매핑
   │     - 간호사 (KNOW ID xxx)
   │
   ├── NCS 매핑 (능력단위 다수)
   │     - 환자 관찰 (NCS-06010101-04)
   │     - 약물 투여 (NCS-06010101-05)
   │     ...
   │
   └── KECO 매핑
         - 간호사 (KECO 2491)
```

**매핑 도구**:
- 직업명 일치 검색 (1차)
- 임베딩 유사도 (2차, BGE-m3-ko 사용)
- 인간 분석가 확인 (3차)

## 6.2 단계별 워크플로 (실전 예시: 간호사)

KSCO 세분류 "간호사"(2491)를 예시로 직무기술 정의서 작성의 전 과정을 따라갑니다.

### 6.2.1 Step 1 — 텍스트 통합

```
[input]
- KSCO 분류항목표: 직업 정의 + 주요업무 5개 항목
- 한국직업사전: 간호사 + 전문간호사 5종 = 약 8,000자
- KNOW: 간호사 능력·지식·직업가치 다차원 데이터
- NCS: 능력단위 약 40개 = 약 30,000자

[처리]
1. 모든 텍스트를 정형화 (HWPX → 텍스트, 정규식 정제)
2. 한 직업 단위로 통합 코퍼스 생성
3. 중복 제거 (임베딩 유사도 > 0.95 문장 통합)

[output]
간호사_통합텍스트.json
  - 직업 정의 (KSCO 출처)
  - 주요 업무 항목 (KSCO + 한국직업사전 출처)
  - 능력 단위 항목 (NCS 출처)
  - 다차원 속성 (KNOW 출처)
```

### 6.2.2 Step 2 — TASK 후보 추출 (LLM 생성)

#### Prompt

```
당신은 직업분석 전문가입니다. 다음 직업 설명에서 직업특수 과업(task) 후보를 추출하세요.

직업: 간호사 (KSCO 2491)
설명:
[Step 1에서 만든 통합 텍스트]

TASK 후보 작성 규칙:
1. 동사로 시작하는 1문장 진술
2. 동사 + 목적어 + (선택적) 도구·맥락
3. 직업특수적 (다른 직업으로 일반화 어려운 수준)
4. 너무 광범위하거나 추상적이면 안 됨
5. 한국어 자연스러운 표현

응답 형식:
{
  "tasks": [
    {
      "id": "T001",
      "statement": "...",
      "source_segment": "...(설명에서 근거 발췌)..."
    },
    ...
  ]
}
```

#### 결과 예시

```json
{
  "tasks": [
    {
      "id": "T001",
      "statement": "환자의 활력징후(혈압, 맥박, 호흡, 체온)를 정기적으로 측정한다",
      "source_segment": "환자 상태 관찰 및 활력징후 측정 (KSCO 주요업무)"
    },
    {
      "id": "T002",
      "statement": "의사 처방에 따라 환자에게 약물을 경구·정맥·근육 경로로 투여한다",
      "source_segment": "의사 처방 약물 투여 및 주사 시술 (KSCO)"
    },
    {
      "id": "T003",
      "statement": "환자의 알레르기 정보를 사전 확인하여 약물 투여 전 의사에게 보고한다",
      "source_segment": "한국직업사전 + NCS 약물투여 능력단위"
    },
    ...
  ]
}
```

평균적으로 한 직업당 20~40개의 TASK 후보가 추출됩니다.

### 6.2.3 Step 3 — HumRRO 5-step 의사결정나무 적용

각 TASK 후보를 5-step으로 검증합니다.

#### Step 3.1 — Task 여부 판정 (LLM)

```
Prompt:
다음 진술이 직업특수 과업(task)에 해당하는지 판정하세요.
가능한 카테고리: task / KSAO / GWA / incomprehensible / too broad

진술: "환자의 활력징후를 정기적으로 측정한다"

응답: {"category": "task", "confidence": 0.95, "reasoning": "..."}
```

#### Step 3.2 — 중복 판정 (임베딩)

```
1. 새 task의 임베딩 vec_new 계산 (BGE-m3-ko)
2. 기존 task pool의 모든 임베딩과 cosine similarity 계산
3. 임계 적용:
   - similarity > 0.92 → 완전 중복 (폐기)
   - 0.78 ~ 0.92 → 부분 중복 (병합 검토)
   - < 0.78 → 신규 (채택)
```

#### Step 3.3 — Emerging Task 검증

신규 task가 다른 응답·자료에서 4개 이상 유사 진술과 매칭되는지 확인. 한국에서는 데이터 규모가 작으므로 **임계 2개로 하향 권고**.

### 6.2.4 Step 4 — TASK 풀 확정과 3-tier 분류

#### 풀 확정

```
간호사 TASK 풀 (예시):
T001: 환자의 활력징후를 정기적으로 측정한다
T002: 의사 처방에 따라 환자에게 약물을 투여한다
T003: 환자의 알레르기 정보를 사전 확인한다
T004: 환자 차트에 간호 기록을 작성한다
T005: 환자·보호자에게 약물 부작용을 교육한다
T006: 응급상황에서 심폐소생술을 시행한다
T007: 환자의 통증 수준을 평가한다
T008: 수술 전 환자를 준비시킨다
T009: 다른 의료진과 인계·인수를 진행한다
T010: 환자 가족의 정서적 지지를 제공한다
... (총 25개)
```

#### 3-tier 분류

본 연구는 새로운 설문조사를 수행하지 않으므로, Relevance·Importance는 KNOW의 기존 평정 데이터 또는 SME 패널 평정으로 대체합니다.

```
Core Tasks (Relevance > 60%, Importance > 3.0):
  T001, T002, T003, T004, T006, T007, T009 (7개)

Supplementary A (Relevance > 60%, Importance < 3.0):
  T005, T010 (2개)

Supplementary B (Relevance 10~60%):
  T008, ... (보존)

Non-relevant (Relevance < 10%):
  (없음)
```

### 6.2.5 Step 5 — GWA 41개로 자동 분류

#### LLM few-shot 분류

```
Prompt:
각 task를 O*NET 41개 GWA 중 어디에 속하는지 1차·2차 선택을 제시하세요.

[GWA 41개 정의 동봉]

Task: "환자의 활력징후를 정기적으로 측정한다"

응답: {
  "primary_gwa": "Monitoring Processes, Materials, or Surroundings",
  "primary_id": "4.A.1.b.1",
  "secondary_gwa": "Inspecting Equipment, Structures, or Material",
  "secondary_id": "4.A.1.b.2",
  "reasoning": "환자의 신체 상태를 정기 관찰하는 모니터링 활동이 1차, 활력징후 측정기 사용 측면에서 2차"
}
```

#### 결과 예시

```
T001 환자의 활력징후 측정 → Monitoring Processes (1차) / Inspecting (2차)
T002 약물 투여 → Performing General Physical Activities (1차) / Operating Equipment (2차)
T003 알레르기 정보 확인 → Getting Information (1차) / Inspecting (2차)
T004 간호 기록 작성 → Documenting/Recording Information (1차)
T005 약물 부작용 교육 → Communicating (1차) / Coaching and Developing Others (2차)
T006 심폐소생술 → Performing General Physical Activities (1차)
T007 통증 평가 → Judging the Qualities of Things (1차)
T008 수술 전 준비 → Performing General Physical Activities (1차)
T009 인계·인수 → Communicating (1차)
T010 정서적 지지 → Performing for or Working Directly with the Public (1차)
...
```

각 GWA에 분류된 task 수가 곧 그 직업의 GWA 프로파일입니다.

### 6.2.6 Step 6 — GWA 내 클러스터링 → DWA 후보 도출

간호사 직업 단독으로는 DWA 도출을 할 수 없습니다. **같은 job family(예: 보건의료직)** 내 여러 직업의 task를 합쳐서 군집화해야 합니다.

#### Job Family 정의

본 연구의 권고: KSCO 중분류 57개를 1차 분할 단위로 사용.

```
"간호사"의 KSCO 8차 중분류 = "보건 전문가" (예시 코드 24)
   ├── 의사
   ├── 간호사
   ├── 약사
   ├── 임상병리사
   ├── 방사선사
   ├── 물리치료사
   ├── 작업치료사
   ├── 영양사
   ├── ... 등 보건의료 관련 세분류 모두
```

#### 클러스터링

```
보건의료 중분류 산하 task 풀 (모든 직업 합산) = 약 2,000개 task

GWA "Monitoring Processes, Materials, or Surroundings" 산하:
  - T001 (간호사): 환자 활력징후 측정
  - T101 (의사): 환자 임상 증상 관찰
  - T201 (방사선사): 영상 촬영 중 환자 상태 관찰
  - T301 (물리치료사): 치료 중 환자 반응 관찰
  - T401 (영양사): 환자 식사 섭취 관찰
  - ... (수십 개)

HDBSCAN 클러스터링 결과:
  Cluster 1: [T001, T101, T301, T401, ...] — 환자 상태·반응 모니터링
  Cluster 2: [T201, T501, ...] — 장비·영상 모니터링
  Cluster 3: [outliers]
```

### 6.2.7 Step 7 — DWA Writing (LLM 초안 + 인간 확정)

#### Cluster 1의 DWA 작성

```
Prompt:
다음 task 군집의 공통 활동을 나타내는 DWA 진술문 초안 3개를 작성하세요.
8대 작성 규칙을 준수하세요.

군집 내 task:
- 환자 활력징후를 정기적으로 측정한다
- 환자 임상 증상을 관찰한다
- 치료 중 환자 반응을 관찰한다
- 환자 식사 섭취 상태를 관찰한다

작성 규칙:
[8대 규칙 동봉]

응답: 초안 3개와 각각의 평가
```

LLM 응답 예시:

```
초안 1: "환자의 신체 상태와 반응을 관찰·측정한다"
  - 평가: 동사 시작 ✓, 8학년 ✓, 모호도 낮음 ✓
  - 약점: "관찰·측정" 두 동사 → 다활동 위험

초안 2: "환자 상태와 임상 반응을 모니터링한다"
  - 평가: 단일 동사 ✓, 적정 추상도 ✓
  - 약점: "모니터링" 외래어 — 가독성 약간 저하

초안 3: "환자의 신체 활동과 반응을 점검한다"
  - 평가: 한국어 자연스러움 ✓, 8학년 ✓
  - 약점: "점검"이 의료에서 "장비 점검"과 충돌 가능

권고: 초안 1 또는 2
```

#### 인간 분석가 최종 확정

분석가는 위 초안을 받아 의료 현장에 적합한 최종 표현을 확정:

```
최종 DWA: "환자의 신체 상태와 반응을 관찰한다"

ID: 4.A.1.b.1.I02.D01
  - 4.A.1.b.1: GWA "Monitoring Processes, Materials, or Surroundings"
  - I02: IWA "환자·고객 상태 모니터링" (아직 임시)
  - D01: DWA 첫 번째 (무작위 부여)
```

### 6.2.8 Step 8 — IWA 도출

DWA들을 GWA 분할 없이 다시 군집화하여 IWA를 도출합니다.

```
GWA "Monitoring..." 산하 DWA들:
  D01: 환자의 신체 상태와 반응을 관찰한다 (보건의료)
  D02: 교실 학생들의 학습 진행을 관찰한다 (교육)
  D03: 생산라인 제품 품질을 관찰한다 (제조)
  D04: 매장 고객 행동을 관찰한다 (판매)
  ...

IWA 클러스터링 결과:
  IWA 1: "사람·서비스 대상 상태 모니터링" — D01, D02, D04, ...
  IWA 2: "제품·공정 품질 모니터링" — D03, ...
```

### 6.2.9 Step 9 — TASK → DWA 매핑 정리
