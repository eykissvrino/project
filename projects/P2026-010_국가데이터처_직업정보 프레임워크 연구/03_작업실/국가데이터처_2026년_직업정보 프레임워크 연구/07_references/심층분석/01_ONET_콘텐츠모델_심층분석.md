## 2. 핵심 메시지 5줄 요약

1. O\*NET은 DOT를 대체하기 위해 *재직자(incumbent) 응답 기반*의 데이터베이스형 시스템으로 설계된, **다목적·공통어·확장 가능한** 직업정보 시스템이다.
2. 콘텐츠 모델은 **6개 도메인**(Worker Characteristics / Worker Requirements / Experience Requirements / Occupation-Specific Information / Occupational Requirements / Workforce Characteristics)으로 직업을 다중 각도(multiple windows)에서 기술한다.
3. 각 도메인은 **위계적(hierarchical)** 으로 조직되어 사용자가 분석 목적에 따라 거시·미시 수준을 선택할 수 있다.
4. **교차직업(cross-occupation) 디스크립터**(GWA·Skills·Knowledge·Abilities)와 **직업특수(occupation-specific) 디스크립터**(Tasks·Tools)를 분리해 두 축의 강점(비교 가능성 + 구체성)을 모두 확보한다.
5. 측정은 **Level × Importance** 5점 척도가 표준이며, 자료 수집은 6학년 가독성 수준의 표준화 설문을 다중 채널(CATI / 웹 / 우편)로 분산 운영한다.

## 3. 핵심 개념·구조 정밀 정리

### 3.2 3대 설계 원칙

#### Multiple Windows (다중 관점)
> 단일 직업을 *근로자 속성, 직무 속성, 환경 속성, 시장 속성* 등 여러 측면에서 동시 기술 → 단일 디스크립터의 한계를 보완

#### Common Language (공통 언어)
> 모든 직업에 동일한 디스크립터 세트를 적용 → 직업 간 직접 비교 가능
> *예: "정보 수집(GWA #1)"의 Level 점수를 회계사 vs 외과의사 간 비교 가능*

#### Hierarchical Taxonomies (위계적 분류)
> 각 도메인이 추상도 위계 (예: GWA → IWA → DWA → Task) → 사용자가 분석 목적에 따라 수준 선택
> *정책 설계: GWA 41개 / 직업 상담: DWA 2,069개 / 직무 설계: Task 19,450개*

### 3.3 4대 근본 설계 원리 (1995 프로토타입에서 계승)

1. **사람 속성 vs 직무 속성** 분리 — Worker Characteristics·Requirements vs Occupational Requirements
2. **교차직업 vs 직업특수** 분리 — GWA·Skills·Knowledge vs Tasks·Tools
3. **가변적 요건 vs 비가변적 특성** 분리 — Skills(개발 가능) vs Abilities(상대적으로 안정)
4. **위계적 조직** — 분석 목적에 따른 추상도 선택

### 3.4 측정 방법론

#### 표준 척도
- **Level**: 직무가 요구하는 *복잡성·난이도* (1~7점, BARS 앵커)
- **Importance**: 직무 수행에서의 *중요도* (1~5점)
- **Frequency**: 활동 빈도 (해당 항목)

#### 응답자 전략
- **재직자(incumbent) 중심** — 직무분석가 평정의 우월성에 대한 실증 근거 부족
- 가시성이 낮은 변수(조직맥락 등)는 **관리자 별도 수집**
- 6학년 가독성 수준 → 신규 직업 출현 자동 감지 가능

#### 데이터 수집 채널
CATI(전화) / 웹 응답 / 디스켓 우편 → 다중 채널로 응답률·비용 최적화

## 4. 본 연구에의 적용 매핑

### 4.1 6대 도메인 → 한국형 6대 차원 변환 논리

| O*NET 6도메인 | 본 연구 6차원 | 변환 근거 |
|---|---|---|
| Worker Characteristics (Abilities·Interests·Values·Styles) | **능력 (Abilities)** | Interests·Values·Styles는 워크피디아·KNOW에서 수집 가능 → 단일 차원으로 압축 |
| Worker Requirements (Skills·Knowledge·Education) | **지식 + 기술 (Knowledge + Skills)** | 2개 차원으로 분리 유지, Education은 직능수준(KSCO)으로 흡수 |
| Experience Requirements (Training·Experience·Licensing) | (직능수준 차원에 통합) | KSCO의 직능수준 4단계 정의에 흡수 |
| Occupational Requirements (GWA·DWA·Work Context) | **업무 + 환경 (Work Activities + Work Context)** | 핵심 두 차원으로 1:1 대응 |
| Occupation-Specific (Tasks·Tools) | **도구 (Tools & Tech)** + 직무기술 정의서 본문 | Tasks는 정의서, Tools는 차원으로 분리 |
| Workforce Characteristics (Wages·Outlook) | **(외부 행정 데이터 연계)** | RFP 요구사항인 "행정 데이터 연계 가능 구조"에 부응 |

### 4.2 본 연구 4영역별 활용 매트릭스

| 본 연구 영역 | O*NET 콘텐츠 모델 활용 |
|---|---|
| 영역1 (직무기술 정의서 작성) | Occupation-Specific 디스크립터 4구성(Tasks/Tools/Tech) → 정의서 4섹션 구조 |
| 영역2 (국내외 사례분석) | 6도메인을 비교 매트릭스의 행으로 활용 |
| 영역3 (구조적 틀 마련) | 3대 설계원칙 + 4대 근본원리 → 한국형 6차원의 학술적 정당화 |
| 영역4 (시뮬레이션 검증) | Level × Importance 척도 → 한국형 검증 척도 설계 |

## 5. 착수보고서 인용 가능 표현

> 본 연구의 한국형 6대 차원 프레임워크는 **Peterson 외(2001)가 제시한 O\*NET 콘텐츠 모델의 6개 도메인**을 한국 노동시장의 데이터 가용성과 정책적 활용 맥락에 맞춰 압축·통합한 것으로, 다음과 같은 학술적 정당화에 기반한다.

> 첫째, **다중 관점(Multiple Windows)** 원칙에 따라 직업을 사람 속성·직무 속성·환경 속성의 다축으로 기술하되, RFP가 요구하는 행정 데이터 연계 가능 구조를 위해 인력 특성(임금·전망)은 외부 연계 영역으로 분리한다.

> 둘째, **공통 언어(Common Language)** 원칙에 따라 모든 KSCO 세분류 직업에 동일한 6대 차원 디스크립터를 적용함으로써 직업 간 직접 비교 가능성을 확보한다.

> 셋째, **위계적 분류(Hierarchical Taxonomies)** 원칙에 따라 업무 차원은 GWA → IWA → DWA → Task의 4계층 구조를 한국형으로 재구성하여 정책·교육·HR 다목적 활용을 동시 수용한다.

## 6. 한계·주의점

| 항목 | 내용 | 본 연구 대응 |
|---|---|---|
| **재직자 응답 의존** | O\*NET은 재직자 자기보고 → 한국에서 재직자 패널 구축 비용 과다 | 1차는 KSCO 텍스트 NLP 분석으로 추출 → 2차로 전문가 검증 패널(5인)이 보완 |
| **2001년 기준 모델** | 플랫폼 노동·AI 직무 등 신생 영역 누락 | KECO 2025 신설 분야(AI·플랫폼·반려동물)에 우선 적용 |
| **Workforce Characteristics 외부 의존** | BLS 연계 실패 시 임금·전망 데이터 누락 | 본 연구 6차원에서 분리하고 행정 데이터 연계 영역으로 명시 |
| **정성·정량 혼재 측정 척도** | Level(7점)/Importance(5점) 척도 차이 | 한국형은 Level/Importance 모두 5점으로 통일 검토 |
